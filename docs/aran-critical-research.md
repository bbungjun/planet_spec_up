## 결론

**확률과 데미지는 단위·증가량·역할이 다르다.** 마스터20 콤보 크리티컬의 최신 공식 효과표는 기본 크확10%, 기본 크리 데미지100%,10콤보당 각각6%p·10%p 증가, 최대10중첩이다. 따라서100콤보의 **스킬 효과표**는 크확70%·크리 데미지 표기200%로 읽힌다. 두 수치를 서로 바꾸거나200%를 크확으로 사용하는 근거는 없다. [7/17 공식 패치](https://mapleplanet.co.kr/news/updates/653)

**그러나 ‘표기200%를 실제 피해식의 추가 계수200%p로 바로 쓰고 샤프140을 더해340으로 만든다’는 단계까지 공식 효과표가 검증하지는 않는다.** 이전 조사에서3/24 공통 크리 가산식과7/17 툴팁을 이어 아란 실제 식처럼 설명한 범위는 넓었다. 지금 확인한 자료는 그 적용을 지지하는 근거지만, 출시 후 아란의 기본100 처리·외부 버프 수치 변환을 명시한 완전한 산식/예제/실측은 아니다. 현재 앱의 크리 환산은 **참고 가정**으로 유지해 보고해야 한다. 반대로 현재 식이 틀렸거나 무조건100을 빼야 한다고 확정할 근거도 아직 없다.

## 1. 최신 공식 효과표와 역할 구분

[7/17 툴팁 이미지](https://mapleplanet.co.kr/uploads/e8bbaa513b76693e.webp)를 공개 HTTP로 새로 내려받아 `view_image`로 판독했다. 본문도 새로 열람했다. 마스터20·콤보 어빌리티10 이상 조건이 있으며, 기본확률10/기본데미지100과 중첩당6/10을 각각 명시한다.

```text
C = 현재 콤보(0 이상의 정수)
k = min(10, floor(C/10))
p = 10 + 6k             [% 확률]
Q = 100 + 10k           [공식 툴팁의 데미지 표기값]
```

여기서는 툴팁 Q와 피해식에 넣을 **추가 계수 q**를 다른 기호로 쓴다. Q→q의 정규화가 이번 재조사의 핵심 미확정이다.

| 콤보 C | 중첩 | 크확 p | 데미지 표기 Q |
| --- | --- | --- | --- |
| 0~9 | 0 | 10% | 100% |
| 10~19 | 1 | 16% | 110% |
| 20~29 | 2 | 22% | 120% |
| 90~99 | 9 | 64% | 190% |
| 100 이상 | 10 | 70% | 200% |

p는 크리가 발생하는 빈도에 관여한다. Q는 크리가 발생했을 때의 피해 효과 설명이다. 예를 들어70% 확률이라고 항상 피해가1.7배가 되는 것도 아니며, 표기200%라는 이유로 항상 피해가2배/3배라는 것도 아니다. 실제 비크리 피해·크리 피해의 관계와 스킬 배율이 따로 필요하다.

7/10은 기본 크확10%가 콤보와 무관하게 적용됨을 명시한다. 따라서 스킬을 배운0콤보 상태와 미습득 상태는 다르다. 현재 앱은 미습득의 콤보 크리 기여를0/0으로 둔다. **미습득이어도 외부 샤프/장비 크확이 있으면 전체 크확0으로 단정할 수 없다.** [7/10 추가 패치](https://mapleplanet.co.kr/news/updates/645)

공식 중간 스킬레벨1~19의 효과표는 확보하지 않았다. 이번 자동 모델은 미습득/마스터20만 지원하며 마스터20 수치를 중간레벨에 복사하거나 선형 보간하지 않는다. 원작 중간레벨 자료를 플래닛의 최신 수치로 자동 도입하지 않는다.

## 3. 기본100과 추가 계수 — 확정할 수 없는 지점

3/24 공통식의 스킬 계수를 s, 추가 크리 계수를 q, 기본 피해를 X라 하면:

```text
비크리 Dn = X×s/100
크리   Dc = X×(s+q)/100
고정 조건의 기대 배율 F = ((1-p/100)Dn+(p/100)Dc)/Dn
                        = 1+(p/100)×q/s
```

이 유도는 **q가 실제 가산 추가 계수일 때** 옳다. 전체 크리 배율이 이미 t=2라면 추가 승산분은 t-1이며, t에 또1을 붙여3으로 만들면 기본 피해를 중복 포함한다. 반대로 별도 추가 계수 q=200%p가 공식 사양이라면 s=100에서 크리 피해3X는 중복 계산이 아니라 가산식의 결과다. 어느 해석이 아란에 맞는지 확인하는 단계가 필요하다.

따라서 툴팁 Q=200만으로 `q=200`, `q=Q-100=100`, `Dc=Dn×2` 중 하나를 자동 확정하지 않는다. 7/17의 기본100 복원은 무조건100을 빼라는 주장에 반대되는 근거지만, **표기 단위 변환**과 **실제 보너스 삭제**를 같게 취급해 ‘차감하면 반드시 패치를 되돌린다’고 단정할 수도 없다.

외부 버프도 마찬가지다. 3/24의140/115는 공식 표기이며7/14는 중첩 정상이라고 한다. 그러나 ‘아란 Q200에140을 더해 가산 추가항340으로 사용한다’는 수치 예제를 공식에서 확보하지 못했다. 현재 앱은 그 해석을 선택한 상태이며 실측 확정이 아니다. 이 조사가 곧100 차감 코드 수정의 승인/근거가 되는 것은 아니다.

## 4. 현재 코드가 계산하는 값

이번 코드 읽기 기준 `domain/aran.ts`는 마스터20 효과를 p/Q로 만들고 `calculate.ts`는 Q를 추가항 q처럼 사용한다. 외부 샤프 선택은 하나이며 쓸샾과 샤프30을 동시에 합산하지 않는다.

```text
p_total = p_aran + 수동 추가 크확 + 선택 외부 버프 크확
q_code  = Q_aran + 선택 외부 버프 크리 데미지
F_code  = 1 + p_total/100 × q_code/대표 스킬배율
```

현재 선택값은 쓸샾 크확10/데미지115, 샤프30 크확15/데미지140이다. 3/24가140/115를 직접 뒷받침하지만 크확10/15와 장비/추가확률의 아란 적용·합산 순서는 이번 조사에서 별도 최신 공식 수치 예제로 재확정하지 않았다. 입력 합계100 초과 차단은 D-136의 현행 앱 정책으로 유지한다.

다음은 **현재 코드의 가상 산술**이며 실제 크리 피해/평균 DPS가 아니다. 추가 크확0, 데미지/방어 보정 없음, 마스터20을 고정했다.

| C | 외부 선택 | p_total | q_code | F_code, s100 | F_code, s500 |
| --- | --- | --- | --- | --- | --- |
| 0 | 없음 | 10% | 100 | 1.10 | 1.02 |
| 0 | 쓸샾 | 20% | 215 | 1.43 | 1.086 |
| 0 | 샤프30 | 25% | 240 | 1.60 | 1.12 |
| 100 | 없음 | 70% | 200 | 2.40 | 1.28 |
| 100 | 쓸샾 | 80% | 315 | 3.52 | 1.504 |
| 100 | 샤프30 | 85% | 340 | 3.89 | 1.578 |

기본 대표 배율100은 연계 스킬의 실측 배율이 아니라 정규화용 기본값이다. 같은 콤보에서도 s가 바뀌면 상대 크리 효율이 크게 달라진다. 이 지표를 캐릭터 전체 사냥/보스 DPS 또는 아란 스윙 전체 크리 배율로 보고하지 않는다. 크리효과는 최대 스탯공 계산 자체와도 별도다.

현재 모델은 추가 크확을 수동 공통 입력 하나로 받으며 장비별 크확/크리 데미지 자동 필드가 없다. 장비 잠재의 크리 효과까지 완전히 자동 반영한다고 보고하지 않는다. 크리 마스터 선택 여부·C0·현재 브라우저 세팅은 별도 개념이며 이번 조사에서 사용자 Chrome의 실제 선택 상태를 확인하거나 변경하지 않았다.

### 코드 위치와 입력 상태의 구분

- `features/calculator/domain/aran.ts:3~5`: 마스터20 효과표. `calculate.ts:73~75/91~103`: 선택 외부 버프와 단순 합산. `formulas.ts:26~31`: 단일 대표 배율의 기대 보정.
- `defaults.ts:24`의 마스터 체크 기본값은 false이며 `CharacterPanel.tsx:173`에서 사용자가 선택한다. 체크 해제의0/0은 해당 효과를 제외한 입력 모드이며 실제 게임 스킬을 미습득했다고 자동 확인한 결과가 아니다.
- 최대 스탯공 검산용으로 생성한 Git 제외 초기 세팅 파일은 체크 해제·0콤보였다. 이는 생성 당시 입력 상태만 확인한 것이며, 사용자가 직접 QA 중인 현재 Chrome 값은 조회하거나 같은 상태라고 주장하지 않았다. 0콤보라는 조건만으로 스킬 기여를0/0으로 바꾸면 안 된다.
- `types.ts`의 EquipmentInput에는 장비별 크확/크뎀 자동 필드가 없고 CharacterInput의 수동 추가 크확만 있다. 수동 추가 크뎀 및 중간 스킬레벨 모델도 없다. 문서의 장비 크확을 현재 OCR 자동 합산 지원이라고 해석하지 않는다.
- `calculate.ts:160~171`: 최대 스탯공 계산 뒤 별도 환산 단계에서만 크리 배율을 쓴다. 이전 최대 스탯공 예상값 자체는 이번 크리 해석 문제와 별개다.

연계에 여러 타격이 있으면 기대 피해는 각 타격의 기대값 합계로 계산해야 한다. 타격 i의 비크리 피해 Dn_i·크리 피해 Dc_i·당시 확률 p_i를 알 때 `Σ[(1-p_i)Dn_i+p_i Dc_i]`다(p_i는0~1). 이 기대값의 합에는 판정 독립성이 필요하지 않지만, ‘연계 중 하나라도 크리일 확률’ 등을 계산하려면 판정 상관관계까지 알아야 한다. 모든 타격에 같은100콤보·같은 s를 적용하는 현재 단일 배율 모델로 이를 확정할 수 없다.

## 6. 후속 판단에 필요한 자료와 작업 결과

확률 검증에는 해당 스킬레벨·콤보구간에서 비크리/크리 발생 비율이 필요하다. 데미지 검증에는 같은 장비·스탯·대상에서0/10/100콤보, 버프 없음/쓸샾/샤프30, 서로 다른 스킬배율 두 종류의 일반·크리 피해가 필요하다. 후자를 비교하면 ‘추가 계수 가산’, ‘피해 승산’, ‘Q-100 정규화’, ‘외부 버프의100 처리’ 가설을 구분하는 데 도움이 된다. 소비 스킬은 타격 직전/직후 콤보를 구분해야 한다.
