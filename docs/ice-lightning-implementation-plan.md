# 썬콜 계산기 구현 계획

작성일: 2026-10-01 KST. 상태: 사용자 요청에 따른 구현 제안이며 코드 구현·계산식 확정·새 직업 공개·배포 승인이 아니다. 사용자 결정 기록은 DECISIONS.md의 D-ICE-LIGHTNING-PLAN-001에만 남긴다.

썬콜은 최종 INT·LUK와 능력창의 총마력을 먼저 계산하고, 이어서 선택 스킬 기준의 장비 비교를 제공한다. 물리 직업의 최대 스탯공 공식을 마법 공격력으로 이름만 바꾸어 적용하지 않는다. 첫 구현 단위는 마법 계산에 필요한 데이터·마력 합산·장비 입력/저장·버프이며, 완성 범위에는 사진 등록·후보 비교·옵션 효율·시뮬레이터·직업 선택 연결까지 포함한다. 실제 전체 사냥 DPS는 별도 후속 범위다.

## 조사 근거와 미확정 항목

기준은 기존에 참고한 [2009년 빅뱅 이전 공식 정리](https://ayumilovemaple.wordpress.com/2009/09/06/maplestory-formula-compilation/)와 버전이 명시된 GMS83 추출 자료이며, 플래닛 공식 변경을 우선한다. 특정 KMS 패치나 GMS83 전체를 플래닛과 동일하다고 확정하지 않는다.

- [플래닛 6월 23일](https://mapleplanet.co.kr/news/updates/623)은 길드 마력을2~10, 물리 공격력을1~5로 구분한다. 길드 미적용0을 포함해 썬콜 마력 입력은0~10으로 설계한다. 물리 길드공 저장값을 마력으로 그대로 읽거나 모든 값을 임의 두 배로 바꾸지 않는다.
- [6월 4일](https://mapleplanet.co.kr/news/updates/587)은 메디테이션보다 높은 혼테일 마력 버프가 적용 중이면 낮은 효과를 적용하지 않으며, 엘리먼트 엠플리피케이션의 ON/OFF를 지원한다고 명시한다. 메디테이션·혼테일은 단순 합산으로 구현하지 않는다. 다른 공지의 후속 중첩 변경 여부도 효과별로 확인한다.
- [8월 28일](https://mapleplanet.co.kr/news/updates/700)은 정령의 축복22의 물리공22/마력44, 성주3세트 공/마력5, 연막탄 공/마력10과 다른 버프 중첩, 빅뱅225%×2를 안내한다. 물리 버프의 값·기본 선택을 일괄 복사할 수 없다. 같은 공지의 소환수 방어율/데미지 옵션 변경도 별도 모델에 반영할 근거다.
- [7월 17일](https://mapleplanet.co.kr/news/updates/653)은 마력·마력%·INT% 등의 장비 옵션 존재와 체인 라이트닝 전이 수정을 안내하지만 마력%의 전체 적용 순서는 제시하지 않는다.
- GMS83 [2차](https://maplestory.io/api/GMS/83/job/220/skillbook) 메디테이션20은 마력20, [3차](https://maplestory.io/api/GMS/83/job/221/skillbook) 엠플리피케이션30 데이터는 MP200/피해140, [4차](https://maplestory.io/api/GMS/83/job/222/skillbook) 체인 라이트닝30의 mad는180, 블리자드30은570이다. 모두 원작 참고 수치이며 플래닛 확정 상수로 도입하지 않는다. API의 영문 스킬명도 한국어 스킬명과 별도로 대조해야 한다.
- [3월 14일](https://mapleplanet.co.kr/news/updates/385)은 블리자드의 MP5000·대상10을 안내한다. 구버전의 MP3500·대상15와 다르므로 스킬표 전체 복사는 금지한다.

첫 계산식 확정 전에 확인할 항목은 다음과 같다.

1. 능력창의 마력과 공격력 항목이 각각 무엇을 표시하는지, INT가 총마력에 포함되는 방식.
2. 마력%가 장비 마력에만 적용되는지, INT에서 얻는 마력이나 특정 버프까지 포함하는지와 버림 위치.
3. 메이플 용사와 INT%의 결합 순서가 현재 물리 직업 모델과 같은지.
4. 메디테이션·혼테일·핑크빈·요괴대사·뿌리기·축복·길드·달성·캐시 효과의 마력 증가량과 중첩/교체 관계.
5. 완드·스태프·방패의 실제 착용 조합과 요구 INT/LUK, 속성 무기의 별도 효과 여부.
6. 마법의 샤프 아이즈/장비 크리·속성 약점/반감·방어율 보정 및 스킬별 예외.

구버전 마법 최대 기본 피해 참고식은 `((M²/1000 + M)/30 + INT/200) × 스킬 마법공격력`이다. M의 정의·플래닛 스킬 수치·추가 보정·중간 버림을 확정하기 전에는 이를 현재 게임의 스탯창 수치나 최종 피해로 표시하지 않는다. 특히 물리용 skillPercent와 구버전 mad의 단위를 자동으로 같다고 취급하지 않는다. LUK는 우선 착용 조건·순수 스탯으로 보존하며 물리식처럼 피해식의 부스탯 항에 임의 가산하지 않는다.

## 단계별 구현

| 단계 | 작업 | 단계 완료 기준 |
| --- | --- | --- |
| 1 계산 계약 | 위 미확정 항목을 출처·패치일·확정/참고/미지원으로 정리. 버프 없는 값, INT만 변경, 장비 마력만 변경, 마력% 변경, 메디테이션 ON/OFF의 기준 입력 준비 | 총마력의 각 출처와 적용 순서가 문서화되고 서로 다른 모델을 구분할 수 있음. 실측 없는 가정은 명시 |
| 2 데이터와 저장 | ice_lightning/INT, 마력 고정/%·요구 INT/LUK·무기 분류·방패 추가. 기존 물리 필드/저장값 유지, 썬콜 전용 저장 분리 | 기존 저장을 손상시키지 않고 썬콜 입력을 저장·복원하는 구조. 누락값을 확정0으로 바꾸지 않음 |
| 3 총마력 계산 | mage.ts 또는 동등한 마법 계산 모듈을 만들고 calculateFromSnapshot에서 분기. 공통 스탯/착용 검사 중 의미가 같은 부분만 재사용 | 최종 INT/LUK·총마력·출처별 기여를 반환. INT 변경 시 총마력도 다시 계산하며 기존 물리 결과 불변 |
| 4 썬콜 입력과 버프 | 메용·메디테이션·엠플 ON/OFF·외부 마력 버프/길드/축복을 연결. 탄약 입력 제거. 효과의 선택·저장을 명확히 분리 | 총마력에 들어가는 버프와 피해/공속/생존 효과가 섞이지 않고 프리셋 전환 후 조건 보존 |
| 5 사진과 장비 비교 | 파서 alias·전투옵션 목록·행 검토·마력 재시도·요구치 INT/LUK·완드/스태프/방패 분류 연결. 후보·일괄입력·시뮬레이터 공통 경로 사용 | 사진→검토→장비/후보→저장에 마력과%가 누락/이중 합산되지 않음. 기존 인식 결과 보호 |
| 6 스킬 기준 비교 | 체인 라이트닝의 첫 대상 한 타를 먼저 모델링하고 블리자드 등으로 확장. 속성/보공/총뎀/방무/크리·엠플을 적용 위치별로 구분 | 동일 조건의 교체 전후·상승률·옵션 효율 제공. 전체 사냥 DPS·연쇄 전체 피해로 표시하지 않음 |
| 7 직업 선택과 반영 | 기존 캡틴·아란·신궁 선택에 썬콜을 연결하고 썬콜 페이지/전용 저장을 구성. 이후 요청 환경에 통합 | 기존 직업 전환·저장·이탈 보호 유지. 실제 dev-main/Production 반영은 각 요청 범위에 따름 |

3단계와 6단계의 계산 결과를 분리한다. 총마력만 준비된 단계에서는 후보의 INT/LUK·마력 변화까지만 제공하고 보공·방무를 포함한 전체 피해 상승률이나 기존 환산공 기준 가성비를 만들어 내지 않는다. 스킬 모델이 준비되면 같은 스냅샷에서 기준·후보·+1 옵션·임시 시뮬레이션을 매번 재산출한다. 마법 지표가 없다는 이유로 statAttack=0을 채워 기존 후보 차단 조건에 밀어 넣지 않고, 지표 종류와 지원 상태를 명시적으로 다룬다.

전체 장비 데이터를 한 번에 교체하는 대규모 이관은 피한다. 현재 물리 필드와 구형 저장은 그대로 읽고 새 마력 필드/요구 조건을 호환 방식으로 추가한다. 새 필드 검증과 직업별 화면/계산 선택을 갖춘 뒤 후속 비숍도 사용할 수 있도록 마법 공통 계산과 썬콜 전용 스킬 규칙을 분리한다. 이번 구현 범위를 비숍 구현까지 확대하는 제안은 아니다.

## 스킬 기본값과 화면 제안

아래는 아직 확정하지 않은 기본값 제안이다. 신궁의 마스터·샤프 기본값 결정을 썬콜에 자동 적용하지 않는다.

| 항목 | 제안 | 계산에서의 역할 |
| --- | --- | --- |
| 메이플 용사 | 기존0/20/30 선택과 저장 방식 유지 | 순수 INT/LUK 변화 |
| 메디테이션 | 첫 버전은20레벨 기준 선택을 제공하되 더 높은 교체 버프와 중복 금지 | 총마력 증가. +20은 구버전 참고이며 현행값 확인 후 채택 |
| 엘리먼트 엠플리피케이션 | 마스터 기준 ON을 초기 제안으로 하고 OFF 가능 | 스킬 피해 보정. 총마력 자체에 곱하지 않음 |
| 매직 부스터 | 사용 상태가 필요할 때 별도 표시 | 공격 주기 효과. 총마력/한 타 피해에 공속 배율을 곱하지 않음 |
| 샤프 아이즈 | 기본 없음, 실제 받은 외부 샤프/쓸샾을 선택 | 궁수 본인 패시브 제외. 마법 크리 적용을 확인한 뒤 피해 모델에 연결 |
| 인피니티 | 원작 참고는 MP 소모 면제 | 현대 본섭의 시간 경과 피해 증가를 임의 도입하지 않음 |
| 매직 가드·매직 아머·레지스턴스·씰·의지 | 첫 계산 화면에서 불필요한 수치 입력을 만들지 않음 | 생존·유틸 효과를 마력 보너스로 합산하지 않음 |
| 소환수·아이스 데몬 | 후속 별도 피해/속성 모델 | 본체 총마력·일반 한 타 모델과 분리 |

화면에서는 INT·INT%·LUK·LUK%·마력·마력%를 구분하고, 물리 공격력 버프/탄약 자리를 썬콜의 적용 가능한 마력 출처로 바꾼다. 결과 주 지표는 확인된 능력창 총마력이며 스킬 기준 결과에는 스킬명·레벨·대상 조건을 함께 표시한다. 장비는 스크린샷과 직접입력을 모두 지원하며, 순수 INT/LUK는 기존 정책처럼 숫자로 입력하고 장비 교체로 재배분하지 않는다.

## 후행 QA와 첫 착수 범위

이번 요청은 계획 수립이므로 앱 수정·테스트·빌드·브라우저·서버·실측을 실행하지 않는다. 향후 QA에서 확인할 기준은 지금 정리한다. 기존 신궁의 QA 유예를 썬콜 검증의 영구 면제로 해석하지 않는다.

- 실제 능력창 총마력: 장비 고정 INT·INT%·고정 마력·마력%를 하나씩 바꿔 적용 대상과 버림을 구분한다. 단일 세팅 일치만으로 전체 합격하지 않는다.
- 메디테이션/상위 버프 교체·엠플 ON/OFF·메용·길드마력0~10·캐시·달성 출처가 중복되지 않는지 확인한다.
- 장비 요구 레벨/INT/LUK, 자기 장비를 이용한 착용과 순환 착용, 무기/방패 조합을 확인한다.
- 마력/공격력, 고정/% 및 요구치가 구분되는 실제 새 사진과 기존 물리 사진을 대조한다. 인식 성공은 장비 단위 무수정·정확 저장 기준을 유지한다.
- 같은 장비 비교0, 순수 스탯 불변, 프리셋/직업 전환·구형 저장 보존, 후보/효율/시뮬레이터 조건 일치와 기존 캡틴·아란·신궁 결과 회귀를 확인한다.
- 스킬 비교는 한 타/타수/첫 대상/연쇄 대상·속성·크리·방어율을 구분해 검산한다. 기준0·입력오류·미지원 조건에서 비율을 만들지 않는다.

첫 착수 단위는 **계산 계약 정리 → 마력 데이터/저장 기반 → 총마력 합산과 메디테이션·길드 마력**을 권장한다. 실제 썬콜의 능력창과 장비 툴팁·버프 상태가 있으면 1단계의 미확정 항목을 빠르게 줄일 수 있다. 별도 썬콜 worktree와 Sol6.1 xhigh 구현/Astra 오케스트레이션은 이전 방식에 맞춘 실행 제안이며 이번 계획만으로 생성·구현을 시작하지 않는다.

## 참고 계산기 비교 후속

2026-10-01 사용자가 지정한 행성.com과 초니 법사 계산기를 공개 소스·실제 브라우저의 동일 합성 입력으로 비교했다. [상세 비교 결과](ice-lightning-reference-comparison.md)에서 총마력5사례 일치, 환산 지표 단위 차이, 크리 분모150/100과 구버전 엠플140의 구분, 연속 효율·자기 장비 포함 착용 판정의 차이를 기록했다.

총마력의 구체적인 참고 후보는 `floor((최종INT + 장비마력) × (1 + 마력%/100)) + 마력% 미적용 버프 마력`이다. 두 계산기는 마력%를 최종INT에도 적용하고 정축·여축·일반 버프·길드 마력은 별도 가산한다. 이 일치로 1단계의 후보 모델은 구체화됐지만 게임 실측 또는 사용자 산식 채택이 완료된 것은 아니다. 물리 공식의 공% 범위를 그대로 복사하지 않는다.

행성의 환산마는 피해 지수이고 초니의 실전마력은 마력 역산값이므로 같은 출력으로 비교하지 않는다. 기존의 순수 스탯 고정·자기 장비 제외 착용·합산 크확100% 오류·버림 포함 재계산 정책은 유지한다. 이번 후속은 조사 결과를 계획에 연결한 것이며 구현·공개·배포 승인으로 확대하지 않는다.
