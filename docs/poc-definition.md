# 캡틴 장비 등록·구매 후보 비교 POC

상태: **사용자 최종 확정 — 구현·실사용 검증 완료를 뜻하지 않음**

확정일: 2026-09-27 (KST)

문서 기록 시각: 2026-09-27 01:14:47 KST (UTC+09:00)

변경 반영: 2026-09-27 — D-024에 따라 캐릭터 정보 등록을 능력창 OCR·자동 저장 중심으로 변경했다. 최초 직접 입력을 기본 경로로 삼았던 이전 정의를 대체한다.

이 문서는 이번 POC의 확정 범위와 합격 기준이다. 결정의 이유와 변경 이력은 [DECISIONS.md](../DECISIONS.md)의 D-013 이후 기록에 누적하며, 현재 개발 정책은 [AGENTS.md](../AGENTS.md)를 따른다. 과거 설계 문서와 POC 범위가 다르면 이번 확정 내용을 따른다.

## 1. 증명하려는 것

> 캡틴 유저가 장비 스크린샷으로 자신의 세팅을 정확하고 간편하게 등록하고, 같은 부위의 구매 후보를 현재 장비와 비교해 구매 판단에 필요한 정보를 얻을 수 있다.

등록 편의성과 구매 비교의 유용성을 함께 검증한다. 등록만 편하거나 비교만 가능한 상태로 POC를 완료 처리하지 않는다.

- 최초 검증 참여자: 지인·외부 플래닛 플레이어 3~5명.
- 우선 직업과 비교 범위: 캡틴, 동일 부위의 기존 장비와 구매 후보.
- PC 브라우저를 우선한다. OCR은 방문자의 브라우저에서 실행한다.
- 기존 신궁·나이트로드 기능은 삭제하지 않는다. 초기 검증 인원은 공개 서비스 대상을 제한하는 정책이 아니다.

## 2. 사용자 흐름

1. **내 장비 사진 넣기:** 게임에서 저장한 여러 스크린샷을 한 번에 선택·붙여넣기·드래그 입력한다.
2. **능력창으로 캐릭터 등록:** 스탯·능력창 사진을 브라우저 OCR로 읽어 표시된 캐릭터 정보를 자동 저장한다. 순수 스탯과 추가·최종 스탯을 구분하고 불확실한 값은 확인·수정 후 저장한다. 화면에 없는 필수 전투 조건은 추가 확인한다.
3. **인식 결과 확인:** 원본과 옵션을 확인하고 불확실하거나 잘못 읽힌 값을 수정한다.
4. **내 세팅 저장:** 확인된 원래 장비와 캐릭터 세팅을 현재 브라우저에 저장한다. 기존의 개인 세팅 1개·무기 프리셋 3개 정책을 유지한다.
5. **구매 후보 넣기:** 같은 부위의 후보 사진을 등록·검토하고 구매 가격을 입력한다. 한 개부터 시작해 후보를 추가할 수 있다.
6. **전후 비교:** 선택한 전투 프리셋을 기준으로 현재 환산공·교체 후 환산공·상승률과 구매 가격을 확인한다. 이번 POC는 비교에서 종료한다.

후보를 추가할 때마다 같은 기존 장비를 기준으로 독립 계산한다. 후보끼리 연속 장착한 것으로 계산하거나 기존 장비·저장값을 덮어쓰지 않는다.

## 3. OCR와 정확한 저장

- 품질 목표는 모든 입력 사진의 옵션을 정확히 확인해 저장하는 것이다. 사용자의 확인·수정을 허용하며 무수정 자동 인식 100%를 요구하거나 보장하지 않는다.
- 불확실한 숫자·퍼센트·알 수 없는 옵션은 검토 대상으로 남긴다. 잘못된 값을 그대로 자동 확정하거나 필요한 옵션 누락을 정상 완료로 처리하지 않는다.
- 사진에 **설명창 전체와 마지막 옵션이 보이고 글자가 가려지지 않아야 한다**는 최소 촬영 조건을 주의 문구로 안내한다.
- 전체 화면·창 위치·해상도 등 사용자 환경 차이를 고려한다. 한 사용자의 특정 사진 묶음에 정답이나 좌표를 맞추지 않는다.
- 원본에서 읽을 수 없는 사진은 영역 지정·사진 교체 등 복구 흐름으로 안내한다. 확인되지 않은 값을 추측해 저장하지 않는다.
- 저장 실패 시 기존 세팅과 검토한 결과를 보존한다. 처리 완료와 옵션 정확도는 별도로 검증한다.
- OCR 입력은 **장비 툴팁과 캐릭터 능력창** 두 종류다. 능력창은 전용 필드 해석이 필요하며, 최종 스탯·스탯공·보공 등 합계 표시를 장비 옵션과 중복 가산하지 않는다. 보이는 값과 확인되지 않은 조건을 구분한다. 순수 스탯을 확인할 수 없는 사진에서 임의 역산값을 확정하지 않는다.

POC 정의 확정 당시에는 Tesseract.js가 기본이었다. 2026-09-27 OCR 개선 작업에서 비교 검증 후 장비 인식 기본을 PaddleOCR 한국어 모델로 연결했으며, Tesseract는 회귀 비교용으로 보존한다. 파인튜닝은 수행하지 않았다. 엔진 교체가 능력창 자동 저장이나 모든 사용자 사진의 품질 기준 충족을 뜻하지 않으며, 동일한 품질 목표와 브라우저 실행 조건으로 계속 검증한다.

## 4. 비교 UI와 계산 기준

| 항목 | 확정 내용 |
| --- | --- |
| 주 지표 | 환산공격력. 단순 스탯공 상승률을 주 지표로 대신하지 않는다. |
| 전투 조건 | 사용자가 선택한 카오스 보스·일반 보스·사냥 프리셋 결과를 우선 표시한다. |
| 전후 표시 | 현재 환산공 → 교체 후 환산공, 증감 수치와 상승·하락률을 이해하기 쉽게 표시한다. |
| 캐릭터 스탯 | 선택 프리셋의 주/부스탯(캡틴·신궁 DEX/STR)과 공격력 합계의 현재·교체 후·증감을 후보 카드에 표시한다. |
| 후보 원본 | 카드에서 원본 장비 영역을 미리 보고, 눌러 확대하거나 선택한 전체 원본 이미지를 열 수 있다. 이미지는 임시 후보와 함께만 유지한다. |
| 가격 | 구매 가격, 억 메소 단위, 소수점 허용. 예: 3,000만 메소 = 0.3억 메소. |
| 메소당 상승률 | 기존 장비 대비 환산공 상승률(%) ÷ 구매 가격(억 메소). 1억 메소당 상승률로 표시한다. 가격 누락·0·잘못된 값 또는 비교 미확정이면 표시하지 않는다. |
| 가격에서 제외 | 기존 장비 판매금·수수료를 임의 추정하거나 차감하지 않는다. |
| 후보 추가 | 한 개부터 시작해 추가 가능. 각 후보는 같은 기준 세팅과 독립 비교한다. |
| 후보 입력 | 사진을 넣으면 OCR 분류로 교체 부위를 자동 배정한다. 후보 이름 입력 없이 가격만 직접 입력하며, 반지·여러 목걸이 등 대상이 여러 개이거나 부위 미인식인 경우만 부위를 선택한다. 옵션 검토·불확실한 값의 확인은 유지한다. |
| 저장 | 원래 장비·캐릭터·무기 프리셋만 저장하며 후보 옵션·가격은 영구 저장하지 않는다. |

상승률은 동일 조건에서 `(교체 후 환산공 / 현재 환산공 - 1) × 100`이다. 현재 값이 0이거나 필수 값 누락·계산 오류·착용 불가가 있으면 임의의 상승률을 만들지 않고 이유를 표시한다.

실제 순수 스탯은 고정한다. 후보 장비의 요구 스탯을 맞추기 위해 순수 스탯을 자동 재배분하지 않는다. 기존 장비와 후보는 같은 버프·공격 대상·스킬 조건에서 비교하고, 서로 다른 프리셋의 절대값을 섞어 순위를 매기지 않는다.

행성.com은 환산공 비교 표현과 계산 대조의 참고자료다. 계산식은 실제 게임 측정과 공식 근거로 검증한다. 환산공 상승률을 실제 DPS나 처치 속도 증가율로 단정하지 않는다.

## 5. 이번 POC에서 제외하거나 보류하는 것

- 후보 장비를 내 장비로 확정 장착·저장하는 기능.
- 구매 후보의 영구 저장, 로그인·서버 계정·기기 간 동기화.
- 여러 부위의 구매 우선순위나 예산 안의 장비 조합 추천.
- 자동 점수·최고 가성비 후보 선정·순위·추천 강조. 최신 사용자 요청의 1억 메소당 환산공 상승률 표시는 포함한다.
- 공개 배포와 SEO 완성을 이번 POC 확정만으로 실행하는 것.
- 외부 OCR API로 이미지·텍스트를 전송하거나 과금하는 것.

구매 가격·환산공 변화·1억 메소당 상승률을 제공하고 사용자가 판단한다. 가격 비교 자체는 유지하며, 가성비를 자동 판단하는 기능만 보류한다.

## 6. 합격 기준

참여자 3~5명에 대해 아래 네 가지를 함께 확인한다.

| 기준 | 확인 방법 |
| --- | --- |
| 독립적인 사용 완료 | 개발자가 대신 조작하지 않고 등록·저장·후보 비교를 완료하는지 관찰한다. |
| 저장 정확도 | 사용자 확인 후 저장된 옵션을 원본과 대조한다. 잘못된 값과 필요한 옵션 누락을 확인한다. |
| 비교 정확도 | 동일한 순수 스탯·버프·대상·스킬 조건에서 전후 환산공과 상승률을 별도로 검산한다. 계산 근거와 반올림 기준도 함께 기록한다. |
| 입력 시간 단축 | 동일한 장비를 직접 입력하는 경우와 비교해 스크린샷 등록이 시간을 줄이는지 측정한다. |

소요 시간과 수정 횟수도 함께 기록한다. 촬영·인식 대기·검토에 든 시간을 구분하고 비교 측정 범위를 명시해, 검토 부담을 제외한 시간만으로 편의성을 판단하지 않는다. 특정 시간 상한이나 수정 장수 상한은 확정하지 않았다.

테스트에 사용한 개인 이미지·정답표·상세 결과는 Git 제외 경로 `output/`에 보존한다. 현재 보유 사진 시험이나 자동 테스트 통과만으로 3~5명의 실제 사용자 검증을 대체하지 않는다. 일반 OCR 검증 지침은 [ocr-validation.md](ocr-validation.md)를 따른다.

## 7. 구현 상태와 후속 작업

정의 확정 시점에는 브라우저 OCR·검토·세팅 저장·무기 프리셋 기반이 구현되어 있다. 다음은 아직 완성해야 할 작업이다.

- 능력창 OCR·조건부 자동 저장·검토·순수 스탯 고정·검산은 2026-09-27 구현했다. 구형 저장값은 보존하고 사진 등록으로 전환한다. 남은 검증은 다양한 환경의 사진과 독립 사용자 흐름이다.
- 캡틴·신궁의 임시 구매 후보 상태·동일 부위 교체 계산은 구현했다. 나이트로드 비교는 STR 모델 보완이 필요하다.
- 선택 프리셋 기준 환산공·스탯공 before/after·차이·상승률·구매 가격 UI는 구현했다. 사용자 독립 완료 검증은 남아 있다.
- 정해진 촬영 조건과 사용자 환경 차이에서 OCR 품질 검증.
- 독립 검산 및 참여자 3~5명의 전체 흐름 검증.

후보 개수의 기술적 한도, 입력값 정밀도·표시 반올림, OCR 엔진 등 세부 구현은 아직 확정하지 않았다. 구현 과정에서 기존 데이터·정확도·단순한 UX를 보존하며 구체화하고, 제품 범위를 바꾸는 결정은 별도로 기록한다.
