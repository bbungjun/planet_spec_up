# 게임 화면 인식 사이트 조사

확인일: 2026-09-28 KST. 대상: [플래닛 군장검사](https://game-stat-reader-20260928.lynn1108.chatgpt.site/reader).

공개 HTML/JavaScript와 별도 Chromium 브라우저를 확인했다. 일반 웹 조회 도구는 접근하지 못했으나 HTTP와 실제 브라우저에서는 200 응답으로 열렸다. 이번 요청은 인식 방식 조사이며, 엔진 교체·화면 캡처 도입·외부 저장 승인이 아니다.

## 확인한 처리 흐름

```text
게임 화면 선택 → 한 프레임 캡처 → 공유 종료
→ 색상으로 상태창 위치·배율 탐지 → 항목별 상대 위치 자르기
→ 브라우저 Tesseract OCR → 숫자 정리·여러 판독 비교
→ 예상 DPS 계산 → 조건 충족 시 익명화 이미지·결과 서버 전송
```

### 입력과 캡처

- `getDisplayMedia`로 사용자가 선택한 화면을 받는다. 오디오 없이 영상 프레임레이트 1을 요청한다.
- 비디오 한 프레임을 Canvas로 PNG로 만든 뒤 모든 트랙을 종료하고 OCR을 시작한다. 지속적으로 게임을 모니터링하는 구현은 아니다.
- 조사 당시 UI의 주 입력은 게임 화면 인식 버튼 하나다. 파일 입력 요소가 없고, 이미지 붙여넣기·드래그 입력 처리도 공개 앱 코드에서 확인하지 못했다. 클립보드 쓰기는 별도의 결과 인장 복사 기능이다.

### 상태창 위치와 숫자 영역

- `colorColumn`은 분홍색·파란색의 특정 RGB 범위에 속하는 픽셀 분포를 찾는다. `detectLayout`은 두 열의 색상 띠와 첫 일곱 행 사이 간격을 이용해 위치와 배율을 정한다.
- 기준 행 간격은 36px이며 추정 배율 0.25~3을 허용한다. 색상과 상대 배치는 고정된 상태창 구조를 전제로 한다. 화면에서 이동한 창이나 동일 구조의 배율 변화는 처리할 수 있으나, 다른 배치·색상까지 일반적으로 탐지하는 구조는 아니다.
- 공개 코드 주석과 `rows`는 제공된 711×692 상태창을 기준으로 측정한 항목 위치를 사용한다. 발견한 색상 열에 대해 직업·레벨·스탯·공격력·퍼센트 옵션의 상대 위치를 계산한다. 한글 항목명이 OCR로 정확히 읽혀야만 필드를 배정하는 방식은 아니다.
- 행을 확대해 읽으며, 스탯의 경우 어두운 픽셀과 글자 간격을 이용해 **첫 숫자 묶음**을 추가로 잘라 확대한다. 흑백 판독용 영상은 밝기 임계값 145로 이진화한다.

### OCR와 결과 정리

- Tesseract.js 및 LSTM WASM을 사용한다. 자산 경로는 같은 사이트의 `/vendor/`이며 브라우저 작업자 두 개를 만든다.
- 직업에는 `korbest+eng`, 숫자 항목에는 `eng` 언어 설정을 사용한다. 모델 이름만으로 학습 자료·품질을 검증한 것은 아니다.
- 레벨을 읽을 때는 `0123456789` 화이트리스트를 설정하고 이후 해제한다. 모든 수치 필드에서 숫자만 출력하도록 제한하는 구현은 아니다.
- 여러 행 분할 모드, 컬러/흑백, 반복 판독을 사용한다. 공격력 범위는 네 번 판독한 뒤 최소·최대 각각의 다수결을 선택한다. 원문과 다른 판독값도 기록한다.
- O→0, I/l→1, 일부 S→5 등 혼동 문자 정규화가 있다. 직업은 별칭과 한글/자모 편집 거리를 이용해 지원 목록의 가까운 이름으로 제안한다.
- 판독값이 없거나 신뢰도가 낮거나 다른 값이 있으면 확인 필요 표시를 붙인다. 하지만 결과 입력 요소는 모두 읽기 전용이라 사용자 숫자 수정 UI는 확인되지 않았다.
- 두 작업자를 만들지만 항목 판독은 순차 루프다. 이번 코드에서 여러 사진의 병렬 처리 흐름은 확인되지 않았다. 완료 시 두 작업자를 종료한다.

## 정확도 판단에서 구분할 사항

### 예시 공격력 정답 치환

`matchKnownAttack`은 입력 크기가 711×692인 경우 같은 사이트의 `sample.png`와 공격력 영역 픽셀을 비교한다. 평균 RGB 차이가 2 미만이면 `readRow`가 OCR 판독 대신 최소 공격력 **17,340**, 최대 공격력 **31,550**를 넣고 신뢰도 100으로 표시한다. 이 영역은 고정 좌표로 비교한다.

이 경로는 예시 이미지의 숫자 형태 대조와 저장된 정답 치환이다. 해당 예시의 결과가 맞는다는 사실을 일반 OCR 정확도의 근거로 쓸 수 없다. 현재 프로젝트의 사진별 정답 치환 금지 기준과 맞지 않으므로 채택 대상으로 삼지 않는다.

### 최종 스탯만 추출

STR/DEX/INT/LUK은 행의 첫 숫자 영역을 읽고 괄호 안의 순수+추가 스탯은 저장 모델로 분리하지 않는다. 현재 우리 앱처럼 네 스탯의 `합계 = 순수 + 추가`를 검증하고 실제 순수 스탯을 고정하는 등록 경로를 대신할 수 없다. 총스탯을 순수값으로 저장하면 장비·버프를 중복 가산할 수 있다.

### 불확실성과 저장

레벨 확인 불가·120 미만·지정된 비정상 범위·DPS 계산 불가·DPS 관련 불안정 항목 3개 이상에서는 저장을 막는다. 이는 우리 앱의 불확실한 값 확인·수정 후 적용 정책과 같은 기준이 아니다. 공개 코드의 저장 조건은 모든 항목의 충돌 해소를 요구하지 않는다. 일부 수치에는 주스탯 300 미만, 총데미지 27% 초과 등 사이트 자체의 임계값도 있으므로 모든 실제 게임 값의 유효 범위라고 간주하지 않는다.

## 데이터 이동

문자 인식은 클라이언트 Tesseract 작업자에서 수행한다. 공개 인식 경로에 외부 OCR/LLM 호출은 없다. 다만 결과 저장은 로컬 전용이 아니다.

- `finishRecognition`은 조건에 따라 별도 저장 버튼 없이 `saveRecognition`을 호출한다.
- 상태창 일부를 잘라 이름·길드·인기도 위치에 검은 마스크를 적용하고, 버프 아이콘과 예상 DPS 인장을 합친 이미지를 만든다. **마스킹 위치도 상대 좌표에 의존하며 모든 개인정보 제거를 보장하는 검증은 하지 않았다.**
- `/api/captures`에 이미지·직업/레벨/스탯 문자열·불안정 항목 수·예상 DPS를 multipart POST한다. 성공 응답의 익명 별명을 표시하는 클라이언트 경로가 있다.
- 익명화 이미지의 로컬 IndexedDB 저장 경로도 있으며 최신 120개를 남기도록 한다.
- 초기 화면의 `/api/rankings` GET 200 응답은 실제 브라우저에서 확인했다. 서버의 내부 OCR 여부·저장 검증·보존 기간·삭제 정책은 공개 프런트엔드만으로 확정할 수 없다. 캡처 POST의 성공 여부는 시험하지 않았다.

## 현재 플래닛 앱과 비교

| 항목 | 조사 사이트 | 현재 프로젝트 |
| --- | --- | --- |
| 기본 OCR | Tesseract.js, 한국어+영어 및 영어 작업자 | PaddleOCR 한국어 PP-OCRv5, ONNX Runtime WASM |
| 능력창 탐지 | 두 색상 열과 기준 행 간격 | STR/DEX 등 텍스트 앵커로 영역 탐지 |
| 필드 분리 | 알려진 상태창의 상대 좌표에서 숫자 영역을 자름 | 위치 있는 OCR 줄을 조합해 라벨·값·순수/추가를 해석 |
| 스탯 등록 | 최종 스탯 첫 숫자 | 순수·추가·최종 구분 및 두 배율 대조 |
| 불확실한 값 | 읽기 전용 표시·조건에 따른 계산/저장 | 사용자 확인·수정 후 적용, 실패 시 기존 세팅 보존 |
| 결과 보관 | 익명 이미지와 결과 서버 POST, 로컬 이미지 경로 | 브라우저 세팅 저장, 이미지·인식 원문 외부 OCR 전송 없음 |

우리 앱에 참고할 부분은 **상태창의 시각적 구조로 영역을 잡고 숫자/괄호 값을 각각 좁혀 읽는 전처리**다. 엔진 교체 없이 현재 Paddle 경로에서도 검토할 수 있다. 색상과 행 간격은 보조 단서로 사용하고 기존 텍스트 앵커·두 판독 일치·순수+추가 검증·사용자 수정 경로를 유지하는 방향이 적절하다. 이는 에이전트 제안이며 도입 결정은 아니다. 엔진별 정확도·속도 우열은 이번 조사에서 측정하지 않았다.

## 검증 범위와 자료

- 실제 브라우저에서 화면 지원 API 존재, 결과 입력의 읽기 전용 상태, 파일 입력 없음, 초기 순위 GET 및 콘솔 오류/경고 0건을 확인했다.
- 공개 코드에서 추출한 위치 탐지 함수에 생성한 색상 띠를 넣어 원위치·이동·1.5배의 세 조건을 확인했다. 실제 게임 사진 정확도 시험은 아니다.
- 공개 `readRow`에 가상 OCR `200 ~ 300`과 예시 일치 조건을 넣으면 17,340/31,550·신뢰도 100으로 치환됨을 재현했다. 일치 조건과 OCR은 모의 값이며 실제 예시 이미지 인식을 수행한 것이 아니다.
- OCR 관련 정적 자산·언어 파일·예시 이미지의 HEAD 200 응답을 확인했다. 예시 이미지 원문을 다운로드하거나 사용자 게임 화면을 캡처·전송하지 않았다.
- 조회 당시 인라인 앱 스크립트 SHA-256: `dd72653aadc138fb9d23732a03bf9d7deb2d9f41e15579556838504bb2eca4f7`.
- 원문·정리 코드·모의 검증은 Git 제외 `output/game-stat-reader-research/`에 보관했다. 공개 사이트 코드를 앱이나 공개 문서에 복제하지 않았다. 앱 코드·저장값·계산 정책 변경 없음.
