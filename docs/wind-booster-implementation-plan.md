# 캡틴 윈드 부스터 체크·환산공 치환 구현 계획

작성일: 2026-09-29 KST. 관련 결정: D-165~166. 현재 상태는 계획 작성이며 앱 기능은 구현하지 않았다. 사용자 요청은 윈드 부스터 체크박스와 환산공 치환을 계획하는 것이며, 적용 중에는 배틀쉽 캐논만 사용하는 조건이다. 건 부스터는 항시 적용하는 기본 버프로 고정한다. 다른 스킬의 피해 비중·공속 효과·전체 사냥 순환을 이번 모델에 넣지 않는다.

## 범위와 미확정 수치

- 체크 해제: 기존 최대 스탯공·환산공·크리 계산을 그대로 사용한다.
- 체크: 캡틴의 배틀쉽 캐논 전용 조건에서 환산공 표시값을 공속 보정 지표로 치환한다. 절대 DPS·실제 한 타 피해로 표시하지 않는다.
- 캐릭터 선택·장비·순수 스탯·장비 공격력·공격력%를 바꾸는 기능으로 확대하지 않는다. 기존 공격력 버프와 함께 켤 수 있다.
- 입력 상태는 프리셋 공통이며 세 무기 프리셋을 바꾸거나 후보를 추가해도 유지한다. 같은 버프 조건을 현재 장비와 후보 양쪽에 적용한다.
- 건 부스터는 ON/OFF 입력·체크박스·별도 저장 항목을 만들지 않는다. 윈드 부스터 미적용과 적용 양쪽에서 이미 건 부스터를 사용한 조건이며, 그 효과를 윈드 보정에 다시 더하거나 곱하지 않는다.
- 보정률은 `건 부스터만 적용한 캐논 주기 / 건 부스터+윈드 부스터를 적용한 캐논 주기`다. D-164의630→600ms·+5%는 원작 참고 조건이고 플래닛 확정값이 아니다. D-166으로 건 부스터 항시 적용은 확인됐으며 총 공속 표기/종류와 실제 주기·배율은 미확정이다. 이하 구조 계획은 유효하며 숫자는 잠정으로 둔다.
- 초안은630/600=21/20 모델을 한 곳의 설정으로 관리하고 결과에 `공속 추정` 상태를 표시하는 방향이다. 이 값의 채택·제품 활성화 또는 플래닛 실측 완료를 이번 계획만으로 확정하지 않는다. 실제 조건이690→600이면23/20이며, 상한 상태로 간격이 같다면1이다.

## 1. 계산 계약을 먼저 확정

```text
R0 = 기존 calculateConvertedAttack 결과
M = 캐논의 건 부스터만 적용한 주기 / 건 부스터+윈드 부스터 적용 주기
R = 체크 && 캡틴 ? floor(R0 × M) : R0
```

R0는 기존 정수 환산공이고 R은 화면/비교에 사용하는 최종 환산공이다. 원래의 스탯공·데미지·방어·크리 버림을 보존하고 공속 보정 뒤 마지막으로 한 번 더 버린다.630/600 모델에서는 `floor(R0 × 21 / 20)`로 계산해1.05 곱셈의 소수 표현 경계를 피한다. 반복 계산 때 R에 보정을 다시 곱하지 않고 항상 원본 R0에서 출발한다.

예시: R0=30,000이면31,500, R0=30,001이면31,501이다. 총공격력·최대 스탯공은 동일하다. 실제 공속과 피해 상한이 확인되지 않은 참고 지표이며 이 숫자를 실측 DPS로 선언하지 않는다.

캐논 전용 조건의 크리 보정도 일관돼야 한다. 현재 캡틴 기본 스킬 입력은380%지만 사용자가 다른 값으로 수정할 수 있다. 에이전트 제안은 체크 중 snapshot에서 캐논 기준380%를 유효값으로 사용하고, 원래 `character.skillPercent`는 보존해 해제 시 복원하는 방식이다. 이 값은 현행 캡틴 기본값을 사용하는 계획이며 플래닛 캐논의 전 레벨 배율 검증을 뜻하지 않는다. 이 제안을 채택하면 원래 입력이380%가 아닌 경우 변화는 공속 효과만의+5%와 같지 않을 수 있다. 원래 입력이380%인 예시에서만+5%를 약속한다.

무기 공속이 다른 후보까지 정확히 비교하려면 기준/후보 각각의 주기가 필요하다. 현재 장비 스키마에는 공속 숫자가 없으므로 이번 최소 경로는 등록한 총들이 같은 캐논 공속 조건이라는 가정이다. 무기 공속이 달라진 후보에 같은 배율을 적용한 결과를 실제 공속 우열로 주장하지 않는다. 공속 입력/OCR 확장은 별도 작업으로 남긴다.

## 2. 공통 계산 경로에 반영

| 파일 | 예정 변경 |
|---|---|
| `domain/types.ts` | `CalculatorInput.windBooster?: boolean` 추가. 결과에 보정 전 환산공과 적용 배율/근거 상태를 제공하는 메타데이터 추가 |
| `domain/defaults.ts` | 새 세팅의 windBooster=false. 직업 변경/초기화도 기존 기본값 생성 경로를 재사용 |
| `domain/wind-booster.ts` 신규 | 캐논 주기·분수 배율·근거 상태와 보정 순수 함수를 관리. 입력0/배율1/미적용·직업 가드를 명시 |
| `domain/calculate.ts` | snapshot에 체크 상태 전달, 캐논 조건의 유효 스킬 배율 처리, 기존 환산공을 구한 뒤 최종 convertedAttack을 치환 |

`calculateFromSnapshot`에서 한 번 적용해야 현재 결과·후보·옵션 효율·시뮬레이터가 같은 값을 얻는다. 표시 컴포넌트마다 곱하는 방식은 쓰지 않는다. 보정 전 값을 별도로 남겨 원래 계산과 보정 결과를 검산할 수 있게 한다. 별도 메타데이터가 없는 기존 테스트/호출도 보정 없는 결과를 유지한다.

기존 입력 오류·무기 누락·착용 불가·구형 데미지 미분리·크확100% 초과·기준값0 처리는 유지한다. 체크가 검증 오류를 무시하거나 불가능한 비교를 확정하는 경로가 되지 않게 한다. 캡틴 외 직업에서는 체크가 저장돼 있어도 계산에 적용하지 않는다.

## 3. 체크박스와 결과 표시

- `components/AttackSetupPanel.tsx`의 기존 공격력 버프 영역에 캡틴 전용 실제 체크박스 `윈드 부스터`를 추가한다. 기본 해제이며 키보드 Space·접근성 라벨·모바일 터치 영역을 제공한다.
- `CalculatorApp.tsx`에서 체크 상태와 변경 핸들러를 관리한다. 뿌리기·분노의 고정 공격력 계산에는 넣지 않는다.
- ON이면 기존 `환산 공격력` 숫자를 R로 치환하고 짧은 표시 `배틀쉽 캐논 · 공속 보정`을 붙인다. 참고 주기를 사용할 동안만 `공속 추정`을 표시한다. 기본 설명은 결과 한 곳에서 짧게 제공한다.
- `PresetStatWindow.tsx`가 사용되는 현재 결과와 시뮬레이터 결과에 같은 표시를 적용한다. 후보 카드·상세의 환산공도 보정 조건을 표시한다.
- `ResultsPanel.tsx`의 계산 근거에는 보정 전 R0·주기 비율·최종 R을 보여준다. 기존 버프별 최대 스탯공은 변화하지 않는다.
- ON에서 기존 사냥 스킬 표가 캐논 공속 결과로 오해되지 않도록 기존 네 스킬의 참고 표를 숨기는 것을 제안한다. OFF에서는 현재 표를 그대로 제공한다. 새 캐논 한 타 피해/타수 표는 이번 범위에 포함하지 않는다.

## 4. 후보·효율·시뮬레이터 동기화

- `candidates.ts`: 현재/교체 후 모두 같은 체크 상태로 계산하고 보정된 convertedAttack의 차이·상승률을 사용한다. 세 프리셋 상세에서도 상태를 유지한다.
- `candidatePriceEfficiency`: 보정 후 환산공 상승률÷억 메소 가격의 기존 정의를 유지한다. 단위·판매금·자동 추천 정책은 바꾸지 않는다.
- 동일 배율이 양쪽에 들어가면 버림 전 상승률은 같고 마지막 정수 버림으로 아주 작은 차이가 생길 수 있다. 윈드 체크 때문에 모든 후보의 상대 효율이5% 상승한다고 설명하지 않는다.
- `optionEfficiency.ts`: +1 옵션의 기준 snapshot에도 체크를 유지한다. 보정 후 환산공 증가량으로 옵션별 상승률과 주스탯 환산을 다시 구한다. 정수 버림 경계는 재계산으로 처리한다.
- `statSimulation.ts`: 기준·각 행 단독·전체 적용 결과와 적용 후 효율에 동일 상태를 유지한다. 체크 변경 시 결과만 갱신하고 입력 중인 임시 변경량은 보존한다.
- 원래 장비·가격·순수 스탯·후보 이미지를 변경하지 않는다. 후보는 계속 임시이며 원본 세팅만 저장한다.

## 5. 저장과 구형 호환

`storage.ts`는 최상위 키를 엄격하게 검사하므로 windBooster 허용 키와 boolean 검증을 함께 추가한다. 값이 없으면 계산/화면에서false로 취급하고 기존 저장값을 초기화하지 않는다. true/false는 저장·새로고침·불러오기에 유지하며 문자열 `"true"`, 숫자1, null은 유효한 체크 상태로 받아들이지 않는다. v1 형식과 기존 저장 키를 유지한다. 저장에는 선택 상태만 넣고 계산 결과·보정 후 장비값을 넣지 않는다.

## 6. 검증과 완료 기준

1. OFF/구형 저장의 기존 고정 계산 사례가 그대로 통과해야 한다.
2. ON에서 장비 공격력·최종 DEX/STR·총공격력·최대 스탯공은 동일하고 환산공만 지정 모델에 따라 치환되는지 검사한다.380%가 아닌 원래 스킬 입력을 보존하고 ON의 유효값/해제 복원을 별도로 검사한다.
3. 21/20 보정의 정수 경계·0·배율1·반복 토글·비캡틴·오류 조건·무기 누락을 검사한다. 건 부스터는 두 상태의 고정 기준이며 그 효과를 중복 계산하거나 이미 보정된 숫자에 재보정하지 않는다.
4. 현재/후보·세 프리셋·가격 효율·옵션 효율·시뮬레이터의 상태와 숫자가 같은 공통 함수 결과인지 검사한다. 마지막 버림으로 생기는 상승률 차이는 수식으로 검산한다.
5. boolean 저장/복원·구형 값 부재·잘못된 타입·직업 변경/초기화·기존 후보 미저장 정책을 검사한다.
6. 실제 로컬 브라우저에서 체크/해제·프리셋 전환·후보 보존·시뮬레이터 입력 보존·저장/새로고침·PC/모바일 및 콘솔 오류를 확인한다. 합성 입력 검증과 게임 실측을 구분한다.
7. 변경 범위의 집중 테스트 후 전체 Vitest·타입·린트·필요한 Vinext/운영용 빌드 검사를 수행한다. 기능 코드·검증·관련 문서·DECISIONS만 비운영 작업 브랜치에 커밋·푸시하고 원격 SHA를 확인한다. 공개 반영은 D-146의 별도 명시 요청을 따른다.

## 구현 순서

주기/캐논 계수의 기준 확인 → 공통 계산·결과 계약 → 체크박스·조건 표시 → 저장 호환 → 비교/효율/시뮬레이터 통합 → 회귀·실제 브라우저 검증 순서로 진행한다. 현재 문서의 배율·380% 처리·사냥 참고 표 숨김은 에이전트의 구현 제안이며 앱에 이미 적용된 동작이 아니다.
