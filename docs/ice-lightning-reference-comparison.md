# 썬콜 마력 참고 계산기 비교

확인일: 2026-10-01 KST. 대상은 [행성.com 알티 계산기](https://www.xn--oj4b158a.com/)와 [초니 법사 마력 계산기](https://choni-calc.vercel.app/#mag)다. 초니의 실제 계산 문서는 [/mag](https://choni-calc.vercel.app/mag)이며 화면에는 2026-09-13 기준으로 표시됐다. 사이트 표기일을 게임 패치 검증일로 취급하지 않는다.

두 사이트의 공개 HTML/JavaScript와 실제 브라우저 결과를 대조했다. 결론은 **총마력 산식은 일치하지만 환산 지표·크리 기본값·효율 계산의 버림 방식은 구분해야 한다**는 것이다. 아래 숫자는 모두 임의의 합성 입력이며 게임 실측이나 사용자 캐릭터 수치가 아니다.

## 총마력에서 일치하는 모델

```text
I = floor((순수 INT + 장비 INT) × (1 + 장비 INT%/100))
    + floor(순수 INT × 메이플 용사 비율)
M = floor((I + 장비 고정 마력) × (1 + 마력%/100))
    + 마력% 미적용 버프 마력
```

두 사이트는 최종 INT를 총마력에 포함하고, **마력%를 최종 INT와 장비 고정 마력의 합에 적용**한다. 메용으로 증가한 INT도 최종 INT 안에 있으므로 이 단계의 마력%를 받는다. 정축·여축·혼테일 버프·길드 마력은 마력%를 적용한 뒤 별도로 가산한다. 물리 공격력의 장비 공격력만 공% 적용하는 방식과 구분해야 한다.

공개 소스 근거는 행성의 [app.js](https://www.xn--oj4b158a.com/app.js) `totalStat`·`totalMagic`·`dRead`와 초니 [/mag](https://choni-calc.vercel.app/mag)의 `calcWeapon`·`calc`다. 초니의 코드 주석에는 알티/planetscouter JS와 대조한 모델임이 명시돼 있다. 따라서 두 구현의 일치는 독립된 두 번의 게임 검산이 아니다. 플래닛 공식 산식/실측으로 승격하지 않고 우리 마법 모델의 구체적인 참고 후보로 사용한다.

## 같은 입력으로 확인한 결과

기준은 레벨160에 대응하는 순수 INT818/LUK4, 장비 INT100·INT50%, 장비 마력200, 메용20(10%), 정축40·여축24·일반 버프40·길드마력10의 합114다. 장비 요구 LUK4, 그 외 옵션·크리·보공·방무·대상 방어율은0이다. 초니는 순수 INT/LUK를 직접 입력하고 행성은 레벨160·순수 LUK4에서 순수 INT818로 분배되는지 결과창으로 확인했다. 아래 변형은 명시한 항목만 기준에서 바꿨다.

| 조건 | 최종 INT 양쪽 동일 | 행성 총마력 | 초니 최종마력 |
| --- | ---: | ---: | ---: |
| 기준 마력% 0 | 1,458 | 1,772 | 1,772 |
| 마력%18 | 1,458 | 2,070 | 2,070 |
| 마력%18·장비 마력210 | 1,458 | 2,082 | 2,082 |
| 마력%18·일반 버프 마력50 | 1,458 | 2,080 | 2,080 |
| 마력%18·메용30(15%) | 1,499 | 2,118 | 2,118 |

모든 행은 양쪽 사이트의 실제 입력 요소를 조작한 뒤 결과 DOM에서 확인했다. 단순히 같은 식을 두 번 실행해 만든 표가 아니다. 장비 마력+10과 버프 마력+10이 각각+12/+10이 되는 것은 이 조건의 마력% 적용 범위와 버림을 설명한다. 일반 버프 숫자40/50은 시험용 입력이며 특정 게임 버프의 현재 수치를 검증한 값은 아니다.

## 환산마와 실전마력의 단위 차이

두 사이트가 쓰는 기본 피해 지수는 `B = (M²/1000 + M)/30 + I/200`이다. 이 지수 자체를 특정 스킬의 실제 한 타나 DPS로 읽지 않는다.

- 행성은 결과창의 스탯마에 `floor(B)`를 표시한다. 환산마는 여기에 데미지·방어율·크리 배율을 적용하고 다시 버린 피해 지수다.
- 초니는 결과 계산에서 B의 소수 부분을 유지하고 데미지·방어율·크리를 적용한다. 이어서 현재 INT를 고정한 채 같은 지수를 내는 마력으로 이차방정식을 역산하고 반올림해 실전마력으로 표시한다. 코드 주석의 ‘스탯마 버림’이라는 설명과 실제 `dmgBase`의 소수 유지도 구분했다.

마력%18의 기준 조건에 총데미지9%만 추가한 실제 화면 결과:

| 지표 | 행성 | 초니 |
| --- | ---: | ---: |
| 최종 INT | 1,458 | 1,458 |
| 총마력/최종마력 | 2,070 | 2,070 |
| 기본 지수 | 스탯마219 | 기본데미지219.1 표시 |
| 총뎀 반영 결과 | 환산마238 | 사냥 실전마력2,183 |

원시 B는219.12이고 총뎀 반영 원시 지수는238.8408이다. 행성은 `floor(219×1.09)=238`, 초니는 원시 지수를 역산해2,183이다. 238과2,183을 직접 비교해서 오차라고 할 수 없다. 우리 화면에서도 총마력·스킬 기준 피해 지수·마력 역산값 중 무엇을 표시하는지 이름과 단위를 분명히 해야 한다.

## 크리와 효율에서 그대로 도입하지 않을 부분

행성의 [damage-config.js](https://www.xn--oj4b158a.com/data/damage-config.js)는 썬콜/불독의 크리 분모를 엠플150으로 고정하고 비숍은100으로 둔다. 초니의 주력기 스킬 데미지 입력은 기본100이며 수정할 수 있다. 크확15·추가 크리 항140이면 행성의 배율은1.14, 초니의 기본 입력은1.21이다. 초니 입력을150으로 맞추면 배율은1.14로 정렬된다.

마력2,070·총뎀9% 상태에서 실제 화면으로 확인한 결과는 행성 환산마272, 초니 분모100의 실전마력2,450, 초니 분모150의 실전마력2,364다. 단위 차이와 분모 차이가 동시에 있으므로 최종 숫자 하나만 보고 비교하지 않는다. 앞서 확인한 GMS83 엠플30은 [원본 툴팁](https://maplestory.io/api/wz/GMS/83/String/Skill.img/2210001/h30)의 마법 공격140%이며, 행성의150을 현재 플래닛 확정값으로 채택하려면 추가 근거가 필요하다. 이 차이만으로 어느 사이트가 게임상 틀렸다고 판정하지 않는다.

옵션 효율도 양쪽은 소수를 유지하는 방식이다. 행성 `magicFinal`은 INT·메용·마력·피해 지수에서 버림을 생략하고, 초니 `calcOpt`도 INT/마력 및 마력 역산의 소수 부분을 유지한다(메용 기여는 미리 계산한 버림값을 사용). 우리 앱의 실제 +1 입력 후 기존 버림을 포함한 재계산과 다른 기준이다. 참고 사이트와 같은 효율 숫자를 만들기 위해 기존 정책을 조용히 바꾸지 않는다.

크확 경계도 다르다. 행성 `critMult`에는 최종 합계100% 상한 처리가 없고 초니 `calcWeapon`은100으로 제한한다. 이는 공개 소스 확인 결과이며 이번 브라우저에서 초과 크확 입력 시험은 실행하지 않았다. 우리 앱의 합산100% 초과 오류/저장·확정 비교 보류 정책을 유지한다.

## 착용 조건과 입력 정책

초니는 무기 옵션을 포함한 최종 LUK를 최대 요구 LUK와 비교한다. 순수 LUK4·다른 장비 LUK0·무기 LUK100·그 무기 요구100의 합성 입력에서 총LUK104와 ‘여유+4’가 실제 표시됐다. 우리 프로젝트는 해당 장비 자체의 옵션을 착용 조건 충족에 사용할 수 없으므로 이 판정 방식을 그대로 가져오지 않는다. 순차 착용·자기 장비 제외·순환 의존 차단을 유지한다.

행성은 레벨과 순수 부스탯/착용 가정에서 AP를 분배하는 흐름이고 초니는 순수 INT/LUK 직접 입력이다. 실제 캐릭터 AP를 고정하는 우리 정책에는 직접 입력 흐름이 맞는다. 행성의 자동 배분값을 실제 캐릭터 순수 INT로 확정하지 않는다. 개별 부위 입력 제한·기본 장비·미지원 버프도 두 사이트의 UI 규칙이지 게임 규칙의 독립 근거는 아니다.

## 구현 계획에 반영할 내용

1. 총마력의 구체적인 참고 후보를 `floor((최종INT+장비마력)×(1+마력%))+비장비마력`으로 추가한다. 확정 정책/게임 실측 상태는 여전히 구분한다.
2. INT%, 마력%, 장비 마력, 비장비 마력, 메용의 적용 순서를 독립적인 출처 항목으로 둔다. 동일 스냅샷에서 후보·효율·시뮬레이터를 재계산한다.
3. 1차 결과는 최종 INT/LUK·총마력으로 만들고, 후속 피해 지수/환산값은 다른 지표임을 표시한다. 초니식 실전마력 역산은 자동 도입하지 않는다.
4. 엠플140/150·마법 크리·스킬 계수의 단위와 적용 순서는 실측/공식 툴팁 조사 항목으로 유지한다. 메디테이션/상위 버프 중첩 등 기존 공식 근거도 계속 따른다.
5. 기존 순수 스탯 고정·착용 조건·크확 상한·버림 포함 효율·브라우저 내부 인식 정책을 유지한다.

확인 후 두 임시 브라우저 탭의 보이는 입력값을 처음 상태로 복원했고 행성142개·초니130개 입력의 값/체크 차이가0개임을 대조했다. 저장 슬롯 버튼·사용자 사진·사용자 장비 데이터·외부 메시지는 사용하지 않았다. 비교 탭은 닫았다. 공개 소스 사본은 Git 제외 output/ice-lightning-comparison에만 두며 브랜드·화면·소스를 제품에 복사하지 않는다. 이번 작업은 외부 참고 계산기 조사이며 우리 앱의 코드 변경·게임 QA·배포가 아니다.
