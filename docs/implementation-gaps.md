# 캡틴 베타 구현의 부족한 점

확인일: 2026-09-30 KST. 현재 `fix/ocr-auto-recovery` 작업 브랜치의 코드와 문서를 기준으로 평가했다. 캡틴 베타의 기존 기능과 후속 계획을 구분한다. 이 문서는 구현 상태와 남은 검증을 설명하며, 완료율이나 운영 배포 승인을 뜻하지 않는다.

## 1. 호밍 환산공 모델이 앱에 반영되지 않음

사용자가 확정한 모델은 어드밴스드 호밍이 적용된 대상의 환산공을 계산할 때 적용 총데미지·보공 합계에 호밍 20%p를 더한다. 현재 [계산 코드](../features/calculator/domain/calculate.ts)는 호밍 적용 여부를 받지 않아 같은 조건에서 ON/OFF 결과를 구분하지 못한다.

예를 들어 다른 배율이 모두 1이고 기존 데미지 합이 60%라면, 확정 모델의 데미지 배율은 호밍 OFF에서 1.6, ON에서 1.8이다. 최대 스탯공이 10,000이면 이 부분만 적용한 환산공은 각각 16,000과 18,000이다. 이는 모델의 산술 예시이며 실제 캐릭터의 완전한 게임 실측값은 아니다.

**필요한 작업:** 호밍 상태를 입력·저장·계산·표시에 일관되게 연결하고, 현재 장비와 후보 장비에 같은 전투 조건을 적용해 비교한다. 기존 최대 스탯공과 캐논 380%·4타를 임의로 변경하지 않는다. 근거와 미확정 범위는 [캡틴 환산공 QA](captain-converted-attack-qa.md)를 따른다.

## 2. 환산공의 게임 정확도 검증 부족

현재 세팅의 최대 스탯공 일치 사례와 자동 회귀 테스트는 있다. 그러나 그 결과만으로 모든 전투 조건의 환산공 및 후보 상승률이 게임과 일치한다고 확정할 수 없다. [QA 실행표](captain-converted-attack-qa.md#6-엄격한-qa-실행표)에서는 특히 총데미지·보공의 조합과 사냥 적용(Q05), 중간 절사 경계(Q09), 실제 캡틴 장비 A/B 교체(Q15), 스킬 입력 누락 처리(Q18)가 남아 있다.

**사용자 영향:** 장비 후보의 전후 수치가 화면에는 그럴듯하게 표시돼도, 실제 게임의 변화량과 다르면 구매 판단을 잘못 이끌 수 있다.

**필요한 검증:** 순수 스탯·버프·공격 대상·스킬 조건을 고정하고 장비만 바꾼 결과를 수집한다. 순수→최종 스탯→공격력→최대 스탯공→환산공의 중간값과 버림을 별도 계산으로 대조한다. 자동 테스트와 실제 게임 검산의 증거를 구분한다.

## 3. OCR의 ‘오류 수정 0회’ 목표 미달

기본 OCR과 불확실한 값의 검토 경로는 구현돼 있다. 하지만 OCR 오류 때문에 사용자가 누락값을 채우거나 오인식값을 고친 장비는 최신 품질 기준에서 성공 사례가 아니다. 자동 복구 실험은 일부 숫자를 잘못 확정하는 반례가 발견돼 기본 기능으로 활성화하지 않았다. [복구 실험 결과](ocr-verified-recovery-plan.md)의 합성 사례 수치를 실제 사용자 사진 성공률로 해석하지 않는다.

**사용자 영향:** 사진 등록이 중단되거나 추가 수정이 필요할 수 있고, 잘못 읽힌 수치를 자동 확정하면 저장값과 비교 결과도 틀릴 수 있다.

**필요한 작업과 검증:** 숫자 정보가 잘리는 조건을 해결하되 추측으로 빈값을 채우지 않는다. Noto Sans·굴림 및 다른 촬영 조건의 원본 사진에서 장비 단위로 필요한 옵션이 모두 원본과 일치하는지 확인한다. 수동 보정 횟수, 무수정 완전 성공, 미해결 실패, 잘못된 자동 확정을 별도로 기록한다. 상세 절차는 [OCR 검증 문서](ocr-validation.md)를 따른다.

## 4. 독립 사용자 POC 미통과

개발자가 기능을 실행하고 자동 테스트를 통과한 결과만으로 처음 쓰는 사람이 사진 등록부터 저장·후보 비교까지 혼자 마칠 수 있는지는 알 수 없다. 확정된 [POC 합격 기준](poc-definition.md#6-합격-기준)은 독립 사용자 3~5명에 대해 다음 다섯 항목을 함께 확인하는 것이다.

1. 개발자의 조작 도움 없이 등록·저장·후보 비교를 완료한다.
2. OCR 오류·누락값의 수동 보정이 0회이고 필요한 장비 정보가 모두 정확하다.
3. 저장한 옵션이 원본 사진과 일치한다.
4. 전후 환산공과 상승률이 별도 검산과 일치한다.
5. 같은 장비의 직접 입력보다 스크린샷 등록 시간이 짧다.

현재는 이 다섯 조건을 충족한 독립 사용자 결과가 없다. 실패 사진과 재촬영·영역 재지정 사례도 분모에서 제외하지 않고 기록해야 한다.

## 5. 윈드 부스터는 계획 단계

[윈드 부스터 구현 계획](wind-booster-implementation-plan.md)은 있으나 체크박스와 공속 보정 지표는 제품에 구현되지 않았다. 건 부스터를 항시 적용한 상태에서 윈드 부스터 전후의 실제 캐논 공격 주기와 보정률도 미확정이다. 이는 후속 기능이며, 현행 캡틴 베타의 기존 환산공 정확도 및 OCR 검증 결과와 구분한다.

## 권장 순서

1. 확정된 호밍 20%p 가산 모델을 제품 계산에 반영한다.
2. 지원하는 전투 조건의 환산공과 실제 장비 A/B 변화량을 독립 검산한다.
3. OCR 무수정 정확도를 개선하고 다양한 원본 사진에서 측정한다.
4. 독립 사용자 3~5명의 전체 POC를 수행한다.
5. 윈드 부스터는 실제 캐논 주기를 확인한 뒤 별도 구현·검증한다.

2026-09-30 현재 작업 브랜치에서 53개 테스트 파일·528개 테스트, 타입 검사, 린트, Vercel용 로컬 빌드가 통과했다. 이 결과는 코드 회귀와 빌드 검증이며 게임 정확도·독립 사용자 POC·이번 Production 동작 검증은 아니다. 기존 공개 베타가 있다는 사실도 이후 변경의 품질 검증이나 배포 승인을 대신하지 않는다.
