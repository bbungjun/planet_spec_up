# 플래닛 데미지 계산기 MVP 설계

- 작성일: 2026-07-27
- 상태: 사용자 설계 승인
- 기준 사이트: [행성.com](https://www.xn--oj4b158a.com/)

## 1. 목표

길드원이 PC에서 장비 수치를 빠르게 입력하고 스탯 공격력과 환산 공격력을 확인할 수 있는 웹 계산기를 만든다. 계산 결과는 동일 입력에서 행성.com과 정수 단위까지 일치해야 한다.

이번 MVP의 최우선 품질은 입력 피로 감소다. 계산 항목을 긴 표 하나에 모두 노출하지 않고, 장비 슬롯을 선택해 필요한 값만 입력하도록 구성한다. 화면과 계산 엔진은 분리하여 후속 OCR 기능이 같은 계산 엔진을 재사용할 수 있게 한다.

## 2. MVP 범위

### 포함

- PC 우선 반응형 웹 화면
- 직업 3종
  - 궁수: 신궁
  - 해적: 캡틴
  - 도적: 나이트로드
- 수동 장비 옵션 입력
- 레벨, 메이플 용사, 샤프 아이즈, 길드 스킬, 보스 관련 설정
- 순수 부스탯 자동 배분과 수동 재정의
- 스탯 공격력과 환산 공격력 실시간 계산
- 계산 근거 요약 표시
- 브라우저 개인 저장 슬롯 1개
- 카드 입력 모드와 숙련자용 일괄 입력 모드
- 행성.com 기준 결과 대조 테스트

### 제외

- 아이템 스크린샷 업로드와 OCR
- OCR 결과 검수
- 무기 잠재 변경 순위
- 추가 스펙 시뮬레이터
- 주문서 최적화
- 큐브 기대값
- 혼돈 누적 분포
- 플래닛 위키와 자연어 챗봇
- 로그인, 길드 계정, 서버 저장
- 신궁·캡틴·나이트로드 외 직업

제외 항목은 MVP 계산 엔진을 변경하지 않고 별도 입력원 또는 별도 기능 모듈로 추가한다.

## 3. 성공 기준

1. 신궁, 캡틴, 나이트로드 각각의 기준 입력 사례에서 스탯공과 환산공이 행성.com과 정확히 일치한다.
2. 사용자는 마우스와 키보드 어느 쪽으로도 장비 입력을 완료할 수 있다.
3. 입력 도중 다른 장비로 이동해도 값이 사라지지 않는다.
4. 페이지를 새로 열어도 저장 슬롯 1개의 값이 복구된다.
5. 빈 선택 항목은 0으로 처리되며 불필요한 필드 입력을 요구하지 않는다.
6. 오류가 있는 필드는 계산에서 제외되고, 사용자는 오류 위치와 이유를 즉시 확인할 수 있다.
7. 계산 엔진은 UI 프레임워크와 브라우저 저장소에 의존하지 않는다.

## 4. 사용자 흐름

1. 사용자가 직업을 선택한다.
2. 레벨과 기본 버프 프리셋이 해당 직업의 기본값으로 채워진다.
3. 왼쪽 장비 슬롯에서 부위를 선택한다.
4. 중앙 편집기에 선택한 부위의 사용 가능한 옵션만 표시된다.
5. 사용자는 값이 있는 항목만 입력한다. 빈칸은 0이다.
6. `Enter`는 다음 입력칸, `Ctrl+Enter`는 다음 장비로 이동한다.
7. 모든 변경은 오른쪽 고정 결과 패널에 즉시 반영된다.
8. 필요하면 일괄 입력 모드로 전환해 전체 장비를 표 형태로 수정한다.
9. 사용자가 세팅을 저장하면 브라우저의 단일 슬롯을 덮어쓴다.

## 5. 화면 구조

### 상단 바

- 제품명과 현재 기능명
- 초기화
- 카드 입력/일괄 입력 전환
- 저장 상태와 저장 버튼

### 왼쪽 패널

- 직업군, 직업, 레벨, 무기
- 장비 슬롯 목록
- 입력 완료 상태
- 선택된 슬롯 강조

장비에 유효한 값이 하나라도 있으면 완료 표시를 한다. 입력되지 않은 장비는 오류가 아니라 0으로 계산한다.

### 중앙 패널

- 선택한 장비 부위
- 기본 스탯
- 잠재능력 합계
- 착용 요구 스탯과 고급 옵션
- 이전/다음 장비 이동
- 키보드 단축키 안내

직업과 부위에 적용되지 않는 필드는 숨긴다. 모든 필드를 항상 노출하지 않는다.

### 오른쪽 고정 패널

- 환산 공격력
- 스탯 공격력
- 최종 주스탯과 부스탯
- 최종 공격력
- 보공·총뎀, 방어율 배율, 크리 배율
- 현재 직업의 계산식 요약
- 경고와 오류 목록

오류 항목을 선택하면 해당 장비 또는 설정 입력으로 이동한다.

### 일괄 입력 모드

행성.com과 유사한 행·열 표를 제공하되 화면 스타일은 제품 디자인 시스템을 따른다. 카드 입력 모드와 일괄 입력 모드는 같은 상태를 편집하며 전환 시 데이터가 복제되거나 초기화되지 않는다.

## 6. 입력 데이터 모델

### 캐릭터 설정

- 직업: `marksman | corsair | night_lord`
- 레벨
- 메이플 용사: 없음, 20, 30
- 타격당 평균 데미지 비율
- 샤프 아이즈 설정
- 몬스터 방어율
- 보스 공격력과 총데미지 합계
- 방어율 무시
- 추가 크리티컬 확률
- 공격력 비율
- 순수 부스탯 수동값 또는 자동
- 나이트로드 스탯창 STR
- 길드 스킬 적용값

### 장비 옵션

공통 장비 레코드는 다음 의미를 갖는다.

- 부위 식별자
- 주스탯 고정값
- 부스탯 고정값
- 주스탯 비율
- 부스탯 비율
- 공격력 고정값
- 공격력 비율
- 착용 요구 부스탯
- 공격력 비율이 적용되지 않는 평면 공격력 여부

직업과 부위에 따라 사용하지 않는 필드는 UI에서 숨기지만 데이터 모델은 동일한 정규화 형태를 사용한다.

### 저장 데이터

```ts
type SavedSetup = {
  schemaVersion: 1;
  savedAt: string;
  input: {
    character: CharacterInput;
    equipment: Record<EquipmentSlot, EquipmentInput>;
  };
};
```

저장 슬롯은 하나이며 새 저장이 이전 저장을 덮어쓴다. 초기화와 저장 덮어쓰기는 UI에서 명확히 구분한다.

## 7. 계산 엔진 구조

계산 엔진은 다음 순수 함수 단위로 나눈다.

1. `normalizeInput`
   - 빈칸을 0으로 변환한다.
   - 문자열 숫자를 안전한 숫자로 변환한다.
   - 허용되지 않는 값을 오류 목록에 추가한다.
2. `sumEquipment`
   - 부위별 고정 스탯, 비율 스탯, 공격력을 합산한다.
   - 공격력 비율 적용 대상과 평면 공격력을 분리한다.
3. `allocatePureStats`
   - 레벨별 총 AP와 직업 최소 부스탯을 계산한다.
   - 착용 요구치에 필요한 최소 순수 부스탯을 계산한다.
   - 수동값이 있으면 경고와 함께 수동값을 우선한다.
4. `calculateTotalStats`
   - 장비, 비율 스탯, 메이플 용사를 적용한다.
5. `calculateAttack`
   - 공격력 비율 대상과 평면 공격력을 합산한다.
6. `calculateStatAttack`
   - 직업별 주스탯, 부스탯, 무기 상수를 적용한다.
7. `calculateConvertedAttack`
   - 보공·총뎀, 방어율, 크리 배율을 적용한다.
8. `calculateDamageResult`
   - 위 단계를 조합해 결과와 계산 근거를 반환한다.

각 함수는 입력을 변경하지 않고 새 결과를 반환한다.

## 8. 계산 규칙

### 공통

레벨별 순수 스탯 풀:

```text
pool = level × 5 + levelBonus
levelBonus = level ≥ 120 ? 22 : level ≥ 70 ? 17 : 12
```

메이플 용사 비율:

```text
없음 = 0
20 = 0.10
30 = 0.15
```

총스탯:

```text
totalStat =
  floor((pureStat + equipmentFlatStat) × (1 + equipmentStatPercent / 100))
  + floor(pureStat × mapleWarriorRate)
```

총공격력:

```text
totalAttack =
  floor(percentEligibleAttack × (1 + attackPercent / 100))
  + flatAttack
```

몬스터 방어율 배율:

```text
effectiveDefense = max(0, monsterDefensePercent - ignoreDefensePercent)
defenseMultiplier = max(0, 1 - effectiveDefense / 100)
```

크리 배율:

```text
criticalMultiplier =
  1 + (totalCriticalRate / 100) ×
      (totalCriticalDamage / averageHitDamagePercent)
```

타격당 평균 데미지 비율이 0이면 크리 배율은 1로 두고 결과에 크리가 반영되지 않았음을 표시한다.

스탯 공격력:

```text
statAttack =
  floor((mainStat × weaponConstant + subStat + extraSubStat) × totalAttack / 100)
```

`extraSubStat`은 나이트로드 사용자가 입력한 스탯창 STR이며 신궁과 캡틴은 0이다.

환산 공격력:

```text
convertedAttack =
  floor(
    statAttack
    × (1 + bossAndTotalDamagePercent / 100)
    × defenseMultiplier
    × criticalMultiplier
  )
```

### 직업 상수

| 직업 | 주스탯 | 부스탯 | 추가 부스탯 | 최소 부스탯 | 무기 | 무기 상수 | 기본 크리 |
| --- | --- | --- | --- | ---: | --- | ---: | --- |
| 신궁 | DEX | STR | 없음 | 4 | 석궁 | 3.6 | 크확 40%, 크뎀 100% |
| 캡틴 | DEX | STR | 없음 | 4 | 건 | 3.6 | 크확 0%, 크뎀 0% |
| 나이트로드 | LUK | DEX | STR | 25 | 아대 | 3.6 | 크확 50%, 크뎀 100% |

기본 타격당 평균 데미지 비율:

- 신궁: 270
- 캡틴: 380
- 나이트로드: 150

위 값과 공식은 기준 사이트의 공개 화면과 클라이언트 계산 규칙을 행동 계약으로 삼는다.

## 9. 상태와 데이터 흐름

```text
사용자 입력
  → 입력 정규화와 검증
  → 계산 엔진
  → 결과와 경고
  → 고정 결과 패널

사용자 저장
  → 버전이 있는 SavedSetup
  → 브라우저 저장소 슬롯 1개

2단계 OCR
  → OCR 후보값
  → 사용자 검수
  → 현재 MVP와 같은 CharacterInput/EquipmentInput
  → 동일 계산 엔진
```

UI는 계산 결과를 직접 만들지 않는다. OCR도 계산하지 않고 정규화된 입력값만 만든다.

## 10. 오류 처리

- 빈칸은 0이다.
- 숫자가 아닌 값, 음수, 필드별 허용 범위 밖의 값은 오류다.
- 오류 값은 정규화 단계에서 0으로 바꾸고 계산 오류 목록에 포함한다. 마지막 유효값으로 조용히 대체하지 않는다.
- 무기 공격력처럼 결과 영향이 큰 필수 권장값이 비어 있으면 계산은 계속하되 경고한다.
- 경고는 결과를 막지 않는다.
- 오류는 결과 패널과 해당 입력칸에 동시에 표시한다.
- 오류 목록에서 항목을 선택하면 관련 장비나 설정으로 이동한다.
- 초기화 전에는 확인을 받는다.
- 0이 아닌 장비 입력이 있을 때 직업을 변경하면 확인을 받은 뒤 장비와 직업 전용 설정을 초기화한다. 서로 다른 스탯 의미로 기존 값을 재해석하지 않는다.
- 저장 데이터가 손상됐거나 지원하지 않는 버전이면 계산 상태에 합치지 않고 복구 불가 안내를 표시한다.

입력 허용 범위:

| 입력 | 허용 범위 |
| --- | --- |
| 레벨 | 정수 1~200 |
| 장비 고정 스탯·공격력·요구 스탯 | 정수 0~9,999 |
| 나이트로드 스탯창 STR | 정수 0~9,999 |
| 장비 스탯%·공격력%·보공/총뎀% | 0~999 |
| 몬스터 방어율·방무·크리확률 | 0~100 |
| 타격당 평균 데미지% | 0 또는 1~10,000 |
| 순수 부스탯 수동값 | 0~해당 레벨의 순수 스탯 풀 |

## 11. 테스트 전략

### 계산 단위 테스트

- 빈칸과 숫자 정규화
- 장비 고정값과 비율값 합산
- 공격력 비율 적용 대상과 평면 공격력 분리
- 레벨별 AP 풀 경계: 69/70, 119/120
- 메이플 용사 0/20/30
- 순수 부스탯 자동 배분
- 방어율과 방무 단순 차감
- 크리 배율 활성/비활성
- 직업별 스탯공과 환산공
- 모든 버림 위치

### 기준 결과 테스트

신궁, 캡틴, 나이트로드 각각에 대해 다음 고정 사례를 둔다.

- 모든 장비가 비어 있는 최소 사례
- 프리셋에 가까운 일반 세팅
- 비율 스탯과 공격력 비율이 함께 있는 세팅
- 메이플 용사와 샤프 아이즈가 적용된 세팅
- 몬스터 방어율과 방무가 함께 있는 세팅
- 착용 요구 부스탯이 자동 배분을 바꾸는 세팅

각 사례는 2026-07-27 시점 행성.com에 같은 값을 입력해 얻은 스탯공과 환산공을 골든 값으로 저장하며 두 정수 결과를 정확히 비교한다. 이후 기준 사이트가 바뀌어도 골든 값은 자동으로 갱신하지 않으며, 공식 변경을 검토하고 승인한 뒤 별도 변경으로 반영한다.

### UI 테스트

- 장비 슬롯 선택과 완료 표시
- 카드 입력과 일괄 입력의 상태 공유
- `Enter`와 `Ctrl+Enter` 이동
- 오류 항목에서 입력 위치로 이동
- 저장, 덮어쓰기, 새로고침 후 복구
- 직업 변경 시 적용 필드와 기본값 변경

## 12. 후속 확장

### 2단계: OCR

스크린샷 업로드, 이미지 전처리, OCR 후보 추출, 필드 매핑, 신뢰도 표시, 사용자 검수 화면을 추가한다. 검수 완료값은 MVP 입력 모델로 변환한다.

### 3단계: 플래닛 위키와 챗봇

플래닛 문서를 출처와 갱신일을 포함한 지식베이스로 관리하고, 검색 근거를 표시하는 자연어 챗봇을 추가한다. 계산 엔진은 챗봇이 설명에 사용할 수 있지만 챗봇이 계산 공식을 임의로 재구현하지 않는다.

## 13. 비기능 요구사항

- PC 1280px 이상에서 세 패널이 한 화면에 표시된다.
- 작은 화면에서는 결과 패널이 아래로 이동하되 입력 데이터는 유지된다.
- 키보드 포커스가 명확히 보인다.
- 색상만으로 완료·오류 상태를 구분하지 않는다.
- 계산은 입력 변경 후 즉시 완료되어 체감 지연이 없어야 한다.
- 계산식과 직업 규칙은 UI 컴포넌트 밖에 위치한다.
- 후속 직업은 직업 규칙 데이터와 기준 테스트를 추가해 확장한다.
