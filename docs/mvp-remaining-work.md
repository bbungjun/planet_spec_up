# 확정 POC 기준 MVP 잔여 작업

점검일: 2026-09-28 (KST). 확정 POC와 현재 로컬 소스·검증 기록을 대조했다. 커밋되지 않은 구현도 포함하며 구현과 실사용 검증을 구분한다.

요구 변경 반영: 최신 D-107에 따라 능력창 사진 등록을 제거하고 순수 주·부스탯 숫자를 직접 입력한다. D-024의 사진 중심 등록 경로를 대체한다.

## 결론

**현재는 장비 OCR 등록, 순수 스탯 직접 입력·고정·저장 및 구매 후보 비교의 핵심 흐름이 구현됐다.** 미입력 구형 세팅의 추정값은 실제 순수 스탯으로 확정하지 않으며 비교 전에 두 숫자를 입력한다. 다양한 장비 사진 환경과 독립 사용자 검증은 남아 있다.

아래 여섯 묶음에서 1~4의 핵심 흐름은 구현됐으며, 범위·한계와 미완료 검증을 구분한다. 현재 우선 잔여 작업은 5의 OCR 품질 보강과 6의 독립 사용자 검증이다. 구현 파일 수나 기존 테스트 수만으로 완료율을 추정하지 않는다.

## 1. 순수 스탯 직접 입력·고정 — 구현

**상태: 직접 입력·검증·저장·후보 비교 재개 구현.** 직업·레벨과 순수 주/부스탯을 숫자로 입력한다. 한쪽 누락·음수·소수·AP 범위 초과를 검사하며 저장 실패 시 입력과 기존 저장값을 보존한다. 입력한 순수 스탯은 장비·프리셋·구매 후보 교체 시 고정된다. 비교 카드의 입력 버튼은 누락된 필드로 이동하고 두 숫자가 유효해지면 후보와 가격을 유지한 채 비교를 재개한다. 과거 능력창 관측 데이터와 등록된 순수 스탯은 유지한다.

레벨1~220·달성 버프·길드 실제 증가량·착용 요구 조건을 지원한다. 명중률 전체 계산은 미지원이다. 공격력%는 장비 공격력 합계에만 적용하고 나머지 출처는 별도 가산한다.

남은 일: 여러 직업·독립 사용자 환경에서 전체 흐름과 계산 결과 검증.

## 2. 동일 부위 교체 계산 — 핵심 구현

`domain/candidates.ts`에서 현재 기준 세팅을 복사해 한 부위만 교체하고 스탯공·환산공·차이·현재값 대비 변화율을 계산한다. 순수 스탯·버프·대상은 고정하며 후보끼리 누적하지 않는다. 원본과 후보의 오류·착용 조건을 함께 검사하고, 0/필수 값 누락/신규 후보 자체의 요구 조건 미인식에서 상승률을 확정하지 않는다. 기존 보유 장비의 요구 조건 누락을 전체 비교 실패로 취급하지 않는다. 다른 프리셋은 각 프리셋의 원래 무기를 기준으로 독립 비교한다.

캡틴·신궁을 지원한다. 나이트로드는 장비 교체에 따른 STR 합산 모델이 없어 후보 비교를 차단한다. 현재 세팅 계산은 유지한다. 추가 독립 검산과 실사용 환경 검증이 남아 있다.

## 3. 구매 후보 등록·OCR 검토·임시 상태 — 핵심 구현

후보 파일 선택/후보 OCR 영역 붙여넣기·드래그 → OCR 부위 자동 배정·옵션 검토·전체 옵션 확인 → 비교 흐름을 구현했다. 이름 입력 없이 사진의 장비명 또는 자동 번호를 사용하며 사용자는 가격만 직접 입력한다. 반지·펜던트 2칸 등 교체 대상이 여러 개이거나 부위가 미인식된 경우에만 선택을 요청한다. 기존 PaddleOCR·복구·줄 검토를 재사용하되 인식값은 새 후보에만 적용한다. 빈 옵션을 현재 장비에서 상속하지 않으며 요구 조건 누락은 검토 필요다. 후보는 추가/수정/삭제할 수 있고 가격은 양의 소수 억 메소 단위다. 후보와 이미지는 React 메모리에만 있고 내 세팅 저장에 섞이지 않는다. 직업·불러오기·초기화 시 후보를 비우고 OCR 목적지·프리셋 변경 시 늦은 결과를 차단한다.

## 4. 전후·상승률·가격 UI — 핵심 구현

2026-09-28 최신 요청에 따라 선택 프리셋의 최대 스탯공을 위에 크게 표시하고 환산공을 아래에 함께 제공한다. `현재 → 교체 후`, 숫자 차이, 증가/감소율, 가격을 표시한다. 현재 장비를 기준 카드로 두고 + 카드로 후보를 추가해 가로로 나란히 비교한다. 후보 카드에는 캐릭터 주/부스탯·공격력의 현재/교체 후/증감을 표시하고, 원본 장비 영역을 미리 본 뒤 확대하거나 선택한 전체 원본을 열 수 있다. 옵션 수정과 다른 프리셋 상세는 별도 창에서 확인하며 비교 영역에서도 전투 프리셋을 전환할 수 있다. 비교 불가 이유와 조건 미확인을 구분하며 1억 메소당 환산공 상승률을 계산해 비교한다. 자동 점수·추천·최고 후보 배지는 넣지 않는다. 독립 사용자에게 흐름이 이해되는지 검증은 아직 남아 있다.

## 5. OCR 품질·촬영 안내·확인 부담 보강 — 기반 활용 후 검증

**상태: 부분 구현·실사용 품질 검증 필요.** 촬영 안내, 확인 차단과 복구 UI는 이미 있다. 사용자 환경 전체에서 정확한 최종 저장과 직접 입력 대비 시간 단축을 충족한다는 검증은 남아 있다.

할 일:

- 기존 촬영 문구를 설명창 전체·마지막 옵션·가림 방지까지 알아보기 쉽게 정리.
- 기존 개발 자료와 독립적인 사용자 사진으로 영역 탐지, 올스탯·숫자·퍼센트·배경 혼입·옵션 누락 확인.
- 내 장비와 구매 후보 모두 원본 확인·수정·재시도가 같은 품질로 동작하도록 연결.
- 사용자가 확인한 값이 최종 저장/비교까지 유지되는지 검증.
- 기본으로 연결한 PaddleOCR와 전처리·검토 흐름이 합격 기준을 충족하는지 검증. 모델 교체 자체를 MVP 완료로 보지 않으며 Tesseract 비교 어댑터도 보존.

기존 Paddle 시험은 같은 18장에 대비 보정·출력 기호 정리를 적용한 탐색 결과다. 다른 사용자 사진의 검증이나 실제 저장 완료 정확도를 대신하지 않는다. 파인튜닝도 현재 확정된 필수 작업이 아니다.

2026-09-27 구현 진척: 실제 앱에 Paddle 두 배율 인식, 앞쪽 기호 정리, 작은 퀵슬롯 후보 억제, 사용자 확인용 옵션 이름 제안을 연결했다. 같은 18장의 앱 검사에서 추가 확인 없이 검토 가능한 사진은 4→7장, 확인이 필요한 옵션 줄은 29→8개였다. 사진 범위 확인·중복 검토는 별도로 유지한다. 이 결과는 독립적인 새 사용자 검증이나 능력창 자동 저장 완료를 의미하지 않는다.

**완료 기준:** 검증 대상 사진의 확인 후 옵션이 원본과 일치하고, 잘못된 값을 조용히 저장하지 않는다. 인식 대기와 수정 시간을 포함해 등록 편의성을 평가한다.

근거: [검토 차단](../features/calculator/ocr/reviewRecognition.ts), [촬영 안내](../features/calculator/components/SetupImportPanel.tsx), [검증 절차](ocr-validation.md). 개인 원본·상세 시험 결과는 공개 문서에 복제하지 않고 `output/`에 유지한다.

## 6. 전체 흐름 회귀·실사용 3~5명 검증 — 완료 판정

**상태: 기존 자동 테스트는 있으나 새 비교 흐름과 POC 합격 검증은 남아 있다.** 2026-09-26 루트 이전 당시 테스트 224개·타입 검사·린트·빌드가 통과했다. 이는 기존 동작의 검증이며 아직 없는 구매 후보 기능의 검증은 아니다. 이번 보고에서 테스트를 다시 실행한 것은 아니다.

할 일:

- 순수 스탯 고정, 후보 독립 계산, 동일 장비 0%, 프리셋 전환, 가격 입력, 기준값 0·음수 변화·필수값 누락 회귀 테스트.
- 후보 OCR 중 취소·재시도·대상 변경, 내 장비와 저장값 보존, 후보 미저장 통합 테스트.
- 실제 브라우저에서 등록→원본 확인→저장→후보 등록→환산공 비교까지 확인.
- 지인·외부 플레이어 3~5명의 실제 사진과 동일 조건의 수동 입력 기준을 준비.
- 개발자의 조작 도움 없이 사용 완료, 저장 옵션 일치, 독립 검산 일치, 직접 입력 대비 시간 단축을 확인하고 소요 시간·수정 횟수 기록.

**완료 기준:** 위 네 합격 기준의 실사용 결과가 남고, 불일치·중단·수정이 많이 필요한 사례를 숨기지 않는다. 코드 테스트 통과만으로 POC 전체를 합격 처리하지 않는다.

## 권장 진행 순서

1. **순수 주/부스탯 직접 입력·고정**을 기준으로 실제 캐릭터와 계산 결과를 검증한다.
2. **동일 부위 교체 계산과 독립 검산**을 먼저 완성한다.
3. **후보 OCR·임시 상태와 before/after UI**를 연결한다.
4. 기존 OCR 검토를 재사용하면서 **새 환경의 정확도·수정 부담**을 보강한다. 사진 평가 자체는 앞 단계와 병행 가능하다.
5. **전체 흐름 회귀 및 3~5명 검증**으로 합격 여부를 판단한다.

OCR 엔진 변경이나 전면 폴더 재구성을 먼저 끝내야 후보 비교를 시작할 수 있는 것은 아니다. 실제로 변경되는 OCR 계약·후보 상태·저장 책임을 필요한 만큼 분리한다.

## 이번 MVP에 추가하지 않을 항목

- 자동 점수·순위·추천 강조. 사용자 요청의 1억 메소당 상승률은 구현 범위에 포함한다.
- 후보 장착·영구 저장, 여러 부위 최적 조합.
- 새 직업 확장, 로그인·DB·기기 간 동기화.
- 외부 OCR API·파인튜닝의 무조건적 도입.
- POC 정의 확정만을 근거로 한 공개 배포·SEO 실행.

테스트 참여자의 접근 방식은 실제 검증을 준비할 때 정한다. 공개 배포는 별도 작업이며 이번 보고는 배포 승인을 추가하지 않는다.
