19개 동시는 약6.1초에 시스템 여유 RAM이2.3GiB까지 내려가, 설정한2.5GiB 미만 중단 기준에 도달했다. 브라우저 Working Set6GiB 초과·실행10분 초과도 중단 기준이며 해당 시점에는 메모리 기준들이 함께 초과했다. **실제 브라우저 충돌이나 전체19장 완료 시간을 측정한 것은 아니다.** 취소 후 작업자와 시험 브라우저를 해제했다.

## 조건과 측정 방법

- 실행 장치: Intel Core i5-13600KF, 물리14코어·논리20프로세서, 설치 RAM32GiB. 재측정 브라우저는 논리20·메모리32·crossOriginIsolated=false를 보고했다. 다른 장치의 최적값을 뜻하지 않는다.
- 입력: 사용자가 Noto Sans 설정으로 촬영했다고 확인한 기존 `0927_equipment`19장. 원본을 Git 제외 경로로 복사해 고정하고 각 파일 SHA-256을 기록했다. 19개 해시가 모두 달랐다. 실제 사용자 브라우저에는 처리 중인 입력 묶음이 남아 있지 않아 이 기존 자료를 사용했다.
- 엔진: 현재 PaddleOCR 한국어 PP-OCRv5, ONNX Runtime WASM, 작업자당 추론 스레드1·SIMD, 문자 인식 배치6. 모델·전처리·두 배율·요구 조건 추가 판독을 변경하지 않았다.
- 범위: 현재 `recognizeBatch`의 사본에서 동시 처리 하드 상한만19로 풀고 각 설정을 전달했다. 같은 사진 중복 작업 공유·완료 순서와 입력 인덱스 분리·작업자 재사용·취소/종료 처리를 유지했다. 실제 앱의 상한3은 수정하지 않았다.
- 순서: 3→1→2→4→6→19를 수행한 뒤3→6을 재측정했다. 각 시험은 별도 Chromium 세션이며 다른 설정과 동시에 실행하지 않았다.
- 시간: 파일을 브라우저 File로 준비하고 모델 파일의 HTTP캐시를 예열한 뒤 측정했다. `recognizeBatch` 시작부터 정리 완료까지이며 이미지 해시·작업자/모델 초기화·두 배율 및 추가 판독·작업자 해제를 포함한다. 최초 파일/모델 다운로드와 앱의 등록 검토·수정·저장 시간은 제외한다.
- 메모리: Windows에서 시험 브라우저와 그 관리 프로세스/자식 프로세스의 Working Set·Private Bytes를 약1초마다 읽었다. 표는 합산 Working Set이며 OCR 단독 할당량이 아니다. 프로세스 간 공유 페이지가 중복 집계될 수 있고 순간 최대값을 놓칠 수 있다. Private Bytes는 별도 원본 자료에 기록했다.
- CPU: 같은 프로세스 묶음의 누적 CPU시간을 샘플링해20개 논리 프로세서와 계측 기간으로 정규화했다. 초기 샘플 이전의 짧은 작업·종료된 프로세스 일부는 놓칠 수 있는 근사치다. 다른 앱/OS부하는 통제하지 않았다.
- 응답성: 간단한 시험 페이지의50ms 타이머 지연을 기록했다. 완료한 설정들의95백분위 추가 지연은 약12ms였다. 앱의 실제 React 카드 렌더링·클릭 반응 전체를 검증한 수치는 아니다.

## 인식 일치와 한계

완료한7회 시험의 각19장 결과는 기준3개 시험과 모두 일치했다. 입력 인덱스별 최종 OCR텍스트·필드·줄 상태·확인 사유·경고를 비교했으며 시간·엔진 신뢰도·경계 좌표는 비교 해시에서 제외했다. 엔진 처리 오류는0건이고, 확인이 필요한 사진은 모든 완료 설정에서3장으로 같았다.

**이는 동시 처리수를 늘려도 이번 자료의 판독 결과가 같았다는 뜻이며 원본 옵션 정확도100% 검증이 아니다.** 원본 검토와 사용자의 확인은 유지한다. 중단된19개 시험의 미완료 결과는 정확도 비교·속도 순위에 포함하지 않았다.

이번 자료는 한 사용자·Noto Sans 환경의19장이고 큰 이미지·다른 사용자의 사진·굴림·저사양 장치·실제 앱 UI의 부하까지 일반화하지 않는다. 6개가 모든 장치·모든 사진에서 최적이라고 확정하지 않는다.

## 해석과 후속 제안

이 장치와 입력에서는6개 동시 처리가 유리했지만 약5.2GiB의 관측 메모리가 필요했다. 4개는3개보다 약20.1% 빨랐으며 관측 메모리 증가는 약0.39GiB였다. 속도와 메모리 부담을 함께 보면4개도 검토할 수 있다. 19개를 한꺼번에 초기화하면 모델·런타임·중간 계산 버퍼 부담이 급증한다.

기본 자동 처리와 고성능 장치용 설정을 구분하고, 메모리 사용을 줄이는 별도 최적화 시험을 검토할 수 있다. 이는 에이전트 제안이며 자동 상한 확대·GPU 도입·모델 변경 결정은 아니다. 현재 앱은 기존1~3개 정책을 유지한다.
