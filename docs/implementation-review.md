## 판단

**캡틴 단독 베타에 필요한 핵심 흐름은 갖춰졌으며, POC 합격과 공개 서비스 완성은 아직 확인되지 않았다.** 캡틴에도 영향을 주는 계산 경계 문제를 해결하고, 다른 캡틴 사용자가 정확하고 빠르게 끝까지 사용할 수 있는지 검증할 시점이다. 신궁 패시브 누락은 후속 직업 공개 전에 해결할 과제로 분리한다.

전체 요구사항의 검수 항목별 통과율을 산출한 것이 아니므로 임의의 완료 백분율은 붙이지 않는다. 구현 존재, 자동 회귀 검증, 게임 실측, 독립 사용자 검증을 구분한다.

## 우선 수정할 계산 문제

### P1. 합산 크리확률 100% 초과가 일반 계산과 후보 비교에서 허용됨

- 위치: [calculate.ts](../features/calculator/domain/calculate.ts), [formulas.ts](../features/calculator/domain/formulas.ts), [normalize.ts](../features/calculator/domain/normalize.ts).
- 현재 추가 크확 입력만 0~100으로 검사하고 직업 기본·샤프아이즈를 합한 뒤에는 상한 검사나 제한을 하지 않는다.
- 이번에 현재 모듈로 합성 캡틴 입력을 실행했다. 순수 DEX800/STR4, 무기 공100, 요구 조건0, 추가 크확100, 샤프아이즈30에서 크확115%, 크리 배율1.4236842105, 검증 이슈0건을 반환했다. 공110 후보 비교도 `ready`였다.
- 같은 입력에서 변경량0인 추가 스탯 시뮬레이터는 전체 크리확률100% 초과 오류로 차단했다. 따라서 계산 경로 사이의 검증 기준도 다르다.
- [공식 2026-06-23 공지](https://mapleplanet.co.kr/news/updates/623)는 크리확률 툴팁의 최대100%를 명시한다. 이번 확인일에 원문을 다시 열어 확인했다.
- 영향: 해당 조건에서 환산공의 크리 보정과 크확 효율을 과대평가할 수 있다. 모든 장비 비교의 상승률이 반드시 틀린다고 확대하지 않는다.
- 권고: 공통 계산 단계에서 상한 정책과 표시를 일치시키고 일반 결과·후보·옵션 효율·시뮬레이터의 경계 회귀를 함께 확인한다. 이번 평가는 계산을 수정하지 않았다.

### 후속 직업 공개 전 P1. 신궁의 샤프아이즈 패시브가 모델에 빠져 있음

- 위치: [job-rules.ts](../features/calculator/domain/job-rules.ts), [calculate.ts](../features/calculator/domain/calculate.ts).
- [공식 2026-08-28 공지](https://mapleplanet.co.kr/news/updates/700)는 보우마스터·신궁의 샤프아이즈에 마스터 기준 크리확률+10%, 크리데미지+10% 패시브 추가를 명시한다. 이번 확인일에 원문을 다시 확인했다.
- 현재 신궁 기본값은40%/100%, 샤프아이즈30 버프는15%/140%다. 패시브나 습득 수준 입력은 없으며 실제 모듈 결과도 합계55%/240%다.
- 스킬 배율270%에서 현재 크리 배율은1.4888888889다. 공지 보너스를 단순 가산한 마스터 가정값은1.6018518519로, 버림 전 배율 차이는 약7.59%다. 이는 조건부 산술 비교이며 게임 실측/DPS 차이가 아니다.
- 영향: 마스터한 신궁의 환산공 및 옵션 상대 효율에 영향을 줄 수 있다. 최대 스탯공 자체의 오류로 해석하지 않는다.
- 권고: 패시브 습득 조건을 구분해 반영하고 실제 캐릭터로 검산한다. D-095에서 기록했던 미해결 항목이 현재 소스에도 남아 있다.

## 품질과 범위의 부족한 점

### 1. POC의 핵심 가설이 아직 증명되지 않음

[POC 합격 기준](poc-definition.md)은 3~5명이 개발자의 조작 도움 없이 등록·저장·비교를 끝내고, 최종 옵션 및 별도 검산이 일치하며, 직접 입력보다 시간을 줄이는 것이다. 현재 검토한 결정 기록과 검증 문서에는 이 합격을 입증하는 결과가 없다. 개발자 브라우저 조작 성공과 자동 테스트 통과로 대체할 수 없다.

다음 검증은 인식 대기뿐 아니라 촬영·검토·수정·저장까지 걸린 시간, 수정 횟수, 도움 요청, 중단 지점, 저장 오류를 함께 기록해야 한다. 사용자 사진 원문과 상세 결과는 기존 비공개 `output/` 정책을 따른다.

### 2. OCR의 다른 환경 대응과 메모리 부담

[기존 동시 처리 시험](ocr-concurrency-experiment.md)은 한 사용자·Noto Sans 사진19장, i5-13600KF/RAM32GiB에서 수행했다. 기본 상한인3개 동시 처리의 평균은44.5초, 브라우저 프로세스 합산 관측 최대 Working Set은3.92GiB였다. 최초 다운로드와 검토·수정 시간은 제외했으며 OCR 단독 메모리나 보편적인 성능 수치가 아니다.

현재 자산의 모델·WASM은 약43.4MB이며 JavaScript 런타임은 별도다. 코드의 동시 처리 정책은 메모리 정보가 없으면8GB로 간주하고, 충분한 코어가 있으면3개까지 실행한다. 큰 사진 제한도 압축 파일 바이트에 의존한다. 따라서 저사양 장치, 메모리 정보 미제공 브라우저, 압축률이 높은 큰 해상도에서의 성능은 추가 검증 대상이다. 현재 충돌을 재현했다고 주장하는 것은 아니다.

굴림, 개발에 사용하지 않은 사용자 사진, 배율·압축·배경, 최초 로딩 조건을 분리한 정답 대조가 필요하다. 동시 처리 시험에서19장 결과가 같았다는 것은 정확도100% 증명이 아니다.

### 3. 지원 직업과 실제 피해 모델의 범위

[후보 비교](../features/calculator/domain/candidates.ts)는 나이트로드를 명시적으로 차단한다. 캡틴 우선 POC에서는 허용된 범위지만, 세 직업 모두 구매 비교 지원으로 설명할 수 없다.

[캡틴 사냥 스킬](../features/calculator/domain/huntingSkills.ts)은 빅뱅 전 참고 모델이다. 소환수 총데미지 적용은 사용자 확인이 있지만, 자체 공격력·무기 공격력 반영·불릿 제외·상한 등 전체 공식의 플래닛 실측 완료는 아니다. 현재 참고 표시를 유지하면서 검증을 확대해야 한다.

### 4. 회귀 검증 자동화와 문서의 최신성

47개 파일466개 테스트는 중요한 강점이다. 그러나 저장소에 추적되는 CI 워크플로와 실제 브라우저 E2E 실행 체계는 확인되지 않았다. OCR 모의 엔진 테스트는 실제 Worker·WASM·다운로드·이미지 정확도를 대신하지 못한다.

현재 [잔여 작업 문서](mvp-remaining-work.md)의 일부 항목은 이미 구현된 후보 테스트를 미완료처럼 서술하고, [구조 점검 문서](architecture-review.md)는 당시 Tesseract를 기본 엔진으로 설명한다. 날짜가 있는 과거 평가지만 현재 완료 상태의 기준으로 사용하면 혼동이 생긴다. 현재 상태 문서와 과거 조사 기록의 역할을 구분하는 것이 좋다.

OCR 화면에는 실행·취소·재시도·검토·배정 상태가 함께 남아 있다. 전면 재작성보다 공통 검증과 최초/재시도 배정 정책부터 모으는 편이 우선이다.

### 5. 공개 배포와 첫 사용 동선

현재 기본 화면은1440px에서 높이4300px,390px에서7577px였다. 첫 등록 버튼과 고정 바로가기는 있지만 설정·시뮬레이터·비교 사이 이동 부담은 실제 사용자 관찰이 필요하다. 설정을 항상 펼치는 기존 사용자 결정은 유지한 상태에서 평가해야 한다.

Vercel 설정과 production 조건의 메타데이터는 있으나, 실제 배포에서 OCR 자산·캐시·Worker 로딩과 저장 복원을 확인하지 않았다. sitemap/robots 전용 경로도 현재 앱에서 확인되지 않았다. 공개 도메인과 검색 설정은 배포 단계의 남은 일이며, 이번 POC의 실패 사유와 구분한다.

로그인·후보 영구 저장·자동 추천·후보 확정 장착은 현재 범위에서 의도적으로 제외했으므로 미구현 결함으로 점수화하지 않는다.

## 다음 작업 순서 제안

1. 캡틴에도 영향을 주는 크확 합산 상한 및 캡틴 전용 화면 — D-136에서 구현.
2. 캡틴 사용자3~5명으로 실제 등록·저장·후보 비교와 직접 입력 대비 시간 측정.
3. 관찰된 실패를 기준으로 OCR 품질·메모리·검토 동선 개선.
4. CI 및 반복 가능한 브라우저 회귀 정비 후, 별도 승인된 배포 환경에서 자산 전달·도메인·검색 설정 검증.

신궁 패시브 보완과 나이트로드 후보 비교는 D-135의 캡틴 단독 베타 이후 해당 직업의 공개를 준비할 때 다룬다. 캡틴 단독 공개를 위한 화면·기존 타 직업 저장값 보호는 후속 D-136에서 구현했다.

위 순서는 에이전트 제안이다. 이번 작업은 평가 문서와 결정 기록만 추가하며 기능·계산식·OCR·저장 정책을 변경하지 않는다.
