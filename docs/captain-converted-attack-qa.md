## 0. 사용자가 게임에서 직접 확인할 일

**최신 사용자 확인(D-170): 현재 스탯공은 정확히 일치한다. 배틀쉽 캐논은30레벨 기준380%로4번 공격하고, 어드밴스드 호밍을 맞힌 대상 타격 시 피해가20% 증가한다.** 이 세 항목을 다시 모르는 값으로 두거나 같은 자료 제출을 반복 요구하지 않는다. 현재 세팅의 일치를 모든 장비/레벨 경계의 검증으로 확대하지 않으며, 호밍20%의 합연산/별도 곱연산·크리 결합은 아직 확인되지 않았다.

이제 **호밍 적용 방식 → 샤프/크리 → 실제 캐논 장비A/B**를 우선 확인한다. 아래1~3번은 기존 체크리스트이며 이미 확인된 현재 스탯공·캐논 계수/타수·호밍 증가량은 완료로 취급하고, 다른 조건이나 미확정 항목에 필요한 경우에만 추가 수집한다. 기존 장비 사진은 재사용하며 바뀐 장비·옵션만 갱신한다. 확인을 위해 장비 구매·큐브 사용·AP/스킬 초기화를 할 필요는 없다.

모든 캐릭터 레벨·장비 조합을 한 사람이 직접 시험하는 요구는 아니다. 총뎀/보공/방무만 단독으로 바꿀 수 없다면 전체 옵션을 함께 기록하고, 그 자료만으로 어떤 원인을 분리할 수 있는지 에이전트가 판단한다. 장비를 바꾸며 여러 옵션이 달라졌는데 특정 옵션만 검증했다고 결론 내리지 않는다.

코드의 정수 경계·스킬0 입력 처리·후보/효율/시뮬레이션 일관성·저장 호환·회귀 테스트·빌드 검증은 에이전트가 수행할 영역이다. 실제3~5명 독립 사용자 POC는 이후 별도 단계이며 현재 요청자가 혼자 모두 수행해야 하는 것은 아니다. 이번 정리는 새 측정이 실시됐다는 기록이 아니다.

## 1. 검증 대상과 지표의 의미

| 지표 | 의미 | 검증할 기준 |
|---|---|---|
| 최대 스탯공 `S` | 능력창 공격 범위의 오른쪽 정수 | 같은 시점의 최종 DEX·STR·공격력·최대 스탯공 |
| 환산공 `R` | `S`에 총뎀/보공·방어율·크리 기대 보정을 적용한 앱의 비교 지표 | 독립 산술과 일치하고, 지원 조건에서 장비 전후 변화가 타당한지 |
| 실제 한 줄 피해 | 스킬 배율·크리 발생·난수·대상 조건을 거친 피해 | 비크리/크리와 스킬을 분리한 실제 기록 |
| 실제 DPS | 전투 시간당 실제 피해 | 타수·숙련도·공속·이동·배틀쉽 가동률까지 필요. 현재 환산공의 보장 범위 밖 |

게임에 앱과 동일한 이름·산식의 환산공 표시가 있다는 근거는 확보하지 않았다. 따라서 `R`을 게임 숫자 하나와 직접 맞추는 방식으로 QA를 끝낼 수 없다. **입력/스탯공 일치 → 배율의 게임 근거 → 독립 산술 → 같은 조건의 장비 비교 → 저장/UI 일치** 순서로 검증한다.

캡틴 공통 계산·구매 후보 비교를 먼저 검증한다. 신궁 패시브·나이트로드 비교는 이번 캡틴 합격 조건에 넣지 않는다. 사냥 스킬 참고값과 향후 윈드 부스터는 각각 별도 범위를 명시한다. 계산 QA 통과도 [OCR 무수정 POC](poc-definition.md)나 운영 배포 승인 자체를 대신하지 않는다.

## 3. 현재 캡틴 계산식을 재현하는 명세

### 3.1 입력과 스탯공

`PD/PS`는 고정된 순수 DEX/STR, `ED/ES`는 장비+캐시 고정 스탯, `L`은 달성 올스탯, `d/s`는 장비 DEX%/STR%, `m`은 메용 비율이다.

```text
DEX = floor((PD + ED + L) × (1 + d/100)) + floor(PD × m)
STR = floor((PS + ES + L) × (1 + s/100)) + floor(PS × m)
m = 메용0: 0, 메용20: 0.10, 메용30: 0.15

A = floor(장비·캐시 공격력 × (1 + 공격력%/100))
    + 불릿 + 축복 + 길드 공격력 + 공격력 버프 + 달성 공격력
S = floor((3.6 × DEX + STR) × A / 100)
```

스탯%는 해당 출처 합계를 한 번 적용한다. 메용에 장비/달성/캐시 스탯을 다시 넣지 않는다. STR은 이미 `S`에 포함되므로 `R`에서 별도로 더하지 않는다. 선택한 프리셋 무기 하나만 합산한다. 공격력%의 장비 대상 구분은 D-030 사용자 확인을 따르지만, 캐시 공격력의 같은 처리까지 새 실측으로 검증한 것은 아니다.

출처: L01·L02, [equipment.ts](../features/calculator/domain/equipment.ts), [cash-equipment.ts](../features/calculator/domain/cash-equipment.ts), [level.ts](../features/calculator/domain/level.ts). 순수 스탯 미등록 시 코드의 추정 배분 경로가 남아 있으므로 확정 후보 비교용 실측 입력은 반드시 두 순수 값을 지정한다.

### 3.2 스탯공에서 환산공으로

```text
D = 총데미지 합계 + (보스일 때만 보공 합계)
    보공에는 장비·캐릭터·길드 패시브·활성 길드10%가 포함됨
I = 장비·캐릭터·길드 방무 합계
F = max(0, 1 - max(0, 대상 방어율 - I) / 100)
p = 기본 + 추가 입력 + 샤프의 크확 합계 / 100
c = 추가 크리 데미지(%p)
k = 적용 스킬 배율(%)
C = 1 + p × c/k       (k > 0)
R = floor(S × (1 + D/100) × F × C)
```

사냥은 장비·캐릭터·길드의 보공을 전부 제외한다. 총뎀과 보공의 **가산 결합은 현재 모델**이며 P03의 명칭 변경만으로 증명되지 않는다. 방무는 P02의 차감식이다. 방무가 방어율에 도달하면 추가 효과는0이며 피해 증폭으로 전환되지 않는다. 대상 방어율 입력은 현재0~100이다.

캡틴 기본 크확/추가 크뎀은 코드상0/0, 샤프30은15/140, 쓸샾은10/115, 기본 `k=380`이다. P01은140·115와 가산 구조를 직접 뒷받침한다. 캐논30레벨의380%·4타는U01에서 사용자가 확인했다. 샤프 확률15·10 및 장비 크확 입력의 출처 합산은 별도 대조 대상이다. 현재 추가 크확은 캐릭터 필드로 입력되며 장비별 크확을 자동 합산하는 모델로 가정하지 않는다.

캐논의 크리식 분모는 한 타의380%다. 4타를 이유로 이를1520%로 바꾸지 않는다. 1회 시전의 피해를 따로 계산할 때 타수를 반영하며, 현재 비교 지표R에 무조건4를 곱하는 변경은 하지 않는다. 어드밴스드 호밍20%를 총뎀에+20%p로 합치는지 별도1.2배로 곱하는지는U01만으로 확정하지 않는다.

현재 합산 크확100%는 허용하고 초과는 `CRITICAL_RATE_EXCEEDED` 오류다. 내부 배율은100%로 제한해도 입력 오류가 사라지지 않으며 후보·옵션 효율·시뮬레이션 확정을 보류한다. 구형 총뎀/보공 합산 입력은 출처 분리가 필요하다.

**경계 검토 필요:** `k=0`을 입력 검증이 허용하며 현재 함수는 `C=1`을 반환한다. 이것은 0으로 나누는 것을 피하는 구현 동작이지 크리 조건을 올바르게 입력했다는 뜻이 아니다. 빈 스킬 입력도 포함해, 지원하는 확정 계산에서 허용할 의미를 QA 전에 정해야 한다.

### 3.3 크리 기대 배율의 유도와 한계

같은 기초 피해 `X`, 크리 확률 `p`를 두면 P01의 가산 구조에서 다음이 나온다.

```text
비크리 피해 = X × k/100
크리 피해   = X × (k+c)/100
확률 평균   = X × k/100 × (1 + p×c/k)
```

따라서 현재 `C`의 구조는 설명된다. 그러나 `R`은 최대 스탯공에서 출발하고 `k/100`과 타수를 최종 결과에 곱하지 않으므로 실제 평균 타격 피해가 아니다. 크리 발생 여부의 평균과 최소~최대 난수 전체의 평균도 다르다. `floor(평균)`과 `평균(floor(각 타격))`의 차이도 미검증이다.

같은 스킬·대상·버프·공속에서 누락 항이 장비 교체 전후에 일정하게 곱해지는 경우에만 환산공 변화가 피해 변화의 좋은 근사가 될 수 있다. 숙련도 영향, 호밍의 가산 위치, 상한, 무기 공속, 소환수의 별도 공격력 때문에 이 조건이 깨질 수 있다. ‘상수라서 상쇄된다’는 주장도 확인 없이 사용하지 않는다.

### 행성.com의 호밍 처리 확인 — D-171

2026-09-29 21:56 KST에 [행성.com](https://www.xn--oj4b158a.com/)의 현재 HTML, [app.js](https://www.xn--oj4b158a.com/app.js), [직업 설정](https://www.xn--oj4b158a.com/data/damage-config.js)을 HTTP200으로 직접 확인했다. **공개된 캡틴 계산 경로에는 어드밴스드 호밍20% 자동 적용이 없다.** 호밍 전용 UI·입력·직업 보정 항을 찾지 못했고, 입력부터 결과·효율까지 추적했다.

추가 스펙의 보공·총뎀에20을 입력하면 **일반 데미지 항에20%p를 더하는 가정**이 된다. 호밍 전용 구현이나 게임의 실제 결합식을 검증한 것으로 볼 수 없다. 따라서 이 사이트를 근거로 ‘호밍은 합연산’ 또는 ‘호밍은 별도 곱연산’이라고 확정할 수 없다.

## 7. 실제 게임 검증 절차와 판정 방법

1. 현행 패치·측정 시각·스킬 레벨·무기 공속·불릿·최종 버프·호밍 상태·대상/부위·방어율 근거를 기록한다. 캐논은 건 부스터 항시ON. 윈드OFF 기준을 먼저 확보한다. 캐시/펜던트 활성 상태와 상한·반감·방어 버프도 확인한다.
2. 먼저 메용·공격 버프·장비 옵션을 하나씩 바꿔 능력창을 대조한다. 제안 최소 표본은 서로 다른 캡틴3명, 각3조건(낮은/높은 잠재, 버림 경계 포함)이다. 9조건만으로 모든 조합을 보장하지 않으며, 필요한 경계는 별도 합성 검산/실측으로 보강한다.
3. 같은 대상에 캐논만 사용해 비크리/크리·타수·피해를 구분한다. 우선 방어·반감·호밍 등의 상태가 고정 가능한 조건을 선택한다. 허수아비는 P07의 계측 수단 후보이며 방어율0이나 모든 버프 자동 유지로 가정하지 않는다. 측정 화면의 표시 피해와 누적 피해도 비교한다.
4. 장비 A/B 순서를 교차해 버프 만료·시간 경과 영향을 줄인다. 30~60초 구간3회 이상은 초기 수집 제안이다. 미스·넉백·이동·배틀쉽 파괴·다른 스킬 혼입 구간은 사전 기준대로 별도 표시한다. 이상한 결과만 임의 삭제하지 않는다.
5. 표본 최대값을 이론 최대값과 동일시하지 않는다. 크리/비크리 분리, 타수 및 평균·분산·표본 수와 불확실성을 남긴다. 상대 변화 검증은 동일 스킬의 전후 피해 모델이 먼저 확정돼야 한다. 현재 최대값 기반R과 실제 난수 평균의 차이를 무시하고 평균DPS만 비교하지 않는다.
6. 결정론적 출력은 독립 검산 대비 **정수 오차0**를 목표로 한다. 게임의 중간 버림 차이가 있으면1이라도 원인을 기록한다. 확률적 전후 시험의 제안 기준은95% 신뢰구간과 사전 오차 예산을 함께 사용하는 것이다. 예를 들어±1%p 등가 범위를 선택했다면 차이의 신뢰구간 전체가 그 범위 안에 들어야 통과한다. 넓은 구간이0을 포함하는 것만으로 합격시키지 않는다. 이 임계값은 사용자 확정 수치가 아니다.
7. 작은 옵션 차이가 측정 잡음보다 작으면 표본을 늘리거나 판정을 보류한다. 게임 규칙을 식별하지 못한 상태에서 테스트를 통과시키기 위한 상수 보정·스크린샷별 예외를 추가하지 않는다.

추가로 확보할 자료: 호밍 표식ON/OFF와 샤프 조건을 분리한 캐논 기록, 필요한 건 마스터리/샤프 설명, 같은 대상의 장비A/B 및 총뎀·보공 단독/조합 기록. 공%와 잠재 버림 경계는 다른 조건에서의 보강 대상으로 남긴다. 현재 스탯공 일치·캐논380%/4타·호밍20%는 이미 사용자가 확인했으므로 같은 항목을 다시 미제공으로 취급하지 않는다. 독립적인 영상 실측과는 구분한다.

**현재 비교는 ‘호밍20%를 보공/총뎀 항에 더한다’는 가설에 훨씬 가깝다.** D=60 가산으로H02에서 예측한ON 누적 피해는100,054,627.875이며 관측은 그보다 약0.130% 낮다. 이것은 기대 비율 산술이며 실제 정수 피해의 정확한 예측식은 아니다. 길드5 예시도 관측과 가깝기 때문에 무기보공60만으로 전체D를60이라고 확정할 수 없다.

다음 검증 후보식은 `R_ON = floor(S × (1 + (D+20)/100) × F × C)`다. **실제 앱에 채택한 공식이 아니다.** 현재 한 쌍의 집계값으로는 합연산을 최종 확정하거나 신뢰구간을 산출할 수 없다. 크리 횟수·난수·캐논 전용 타수·표식 유지시간이 없고 크리와의 결합 위치도 독립 분리되지 않았다. 두 조건에서 소환수 피해가 약1.18% 차이 난 것을 소환수 호밍 적용/미적용의 확정 증거로 삼지 않는다.

후속은 이미 확인된 동일 조건을 다시 묻는 대신 **전체 보공/총뎀 수치**를 확보하고, 가능하면 다른D 조건과 동일 조건 반복에서 가산식의 예측을 대조하는 것이다. 이 결과로 계산식·저장/UI·배포 정책을 자동 변경하지 않는다.
