# 메이플플래닛 아란 추가를 위한 조사계획

- 작성·자료 확인일: 2026-09-29 (KST)
- 상태: 조사계획 제안. 핵심 공식 공지의 예비 확인과 현재 코드의 적용 지점 점검을 마쳤다. 전체 패치 조사·게임 실측·아란 구현은 미완료다.
- 요청·결정 기록: [DECISIONS.md D-149](../DECISIONS.md)
- 목적: 아란의 장비 교체 전후 최대 스탯공·환산공을 계산하는 데 필요한 규칙과, 별도 스킬 피해 모델이 필요한 규칙을 근거와 함께 구분한다.

## 1. 조사 순서와 산출물

| 순서 | 조사 내용 | 완료 산출물 |
| --- | --- | --- |
| 1 | 출시부터 조사 실행일까지 공식 공지·패치·추가 수정·이미지 표 대조 | 날짜별 변경표, 현재 적용 후보 규칙, 폐기·정정된 설명 |

단계 1~3의 공개 자료 조사를 먼저 진행할 수 있다. 단계 4의 실측에는 실제 아란 캐릭터 자료가 필요하며, 자료가 없는 항목은 미확정으로 남긴다. 아래 완료 기준은 에이전트 제안이며 사용자 확정 정책으로 취급하지 않는다.

## 4. 데미지 계산에서 검증할 질문

### A. 최대 스탯공과 장비 비교 — 최우선

- STR/DEX 역할, 순수 스탯·AP 범위, 폴암 계수, 무기 요구 조건을 확인한다. 현재 앱의 다른 직업 계수 3.6을 아란에 그대로 복사하지 않는다.
- 최대 스탯공과 실제 공격의 스윙/찌르기 판정, 숙련도가 관여하는 최소·평균 피해를 구분한다.
- 장비 공격력, 콤보 어빌리티, 하이 마스터리, 공통 공격력 버프를 출처별로 나누고 공격력% 대상과 버림 순서를 확인한다.
- 기존 순수 스탯 고정·장비 교체·메이플 용사·스탯% 규칙은 기준으로 보존하며, 아란에 적용되는지는 근거로 검증한다.

### B. 크리티컬과 환산공

- 콤보 카운트 C에 따른 공격력 A(C), 크리확률 p(C), 크리 증가분 q(C)를 각각 정의한다. 수치는 조사 후 채운다.
- 스킬 배율에 크리 증가분을 더하는 방식인지, 최종 피해에 곱하는 방식인지 검증한다. 스킬 배율이 다른 공격 두 종류와 버프 전후를 비교해 가설을 구분한다.
- 현재 공통식 `1 + (크확 / 100) × (크리 증가분 / 스킬 배율)`을 아란에 재사용할 수 있는지 검토한다. 한 스킬 배율이 여러 연계 타격을 대표할 수 있는지도 확인한다.
- 총데미지·보공·방무·속성·분산·크리의 적용 순서, 출처 중첩, 각 단계의 버림을 확인한다. 방어율과 고정 방어력·명중 문제를 분리한다.
- D-136의 합산 크확 100% 초과 입력 차단 정책을 유지한다. 콤보 변화로 상한 문제가 생기는 경우의 입력·표시 요구를 조사 결과에 남기고 임의로 정책을 바꾸지 않는다.

### C. 스킬별 한 타 피해와 분산

- 7월 17일 공지의 분산 감소율 `((N - 1) / N) × (80 - L / 10)%`를 출발점으로, 적용 스킬과 후속 예외를 먼저 확정한다. L은 캐릭터 레벨, N은 실제 타격 대상 수이며 보스 부위가 별도 대상으로 계산되는지도 확인한다.
- 레벨/10의 정수 처리, 대상별 피해 감소인지 전체 피해 분배인지, 크리·상한 처리와의 순서를 확인한다.
- 9월 3일 템페스트 관련 예외를 일반/보스·빙결 유무·현재 공격 스킬별로 나눈다. 모든 아란 스킬에 동일한 분산식을 적용하지 않는다.
- 한 줄 피해, 한 번 사용한 총 피해, 연계 전체 피해, 초당 피해를 따로 정의한다. 랜덤 피해·크리·타수·상한·미스·속성 및 특수 즉사/HP 처리의 포함 여부를 명시한다.

### D. 연계 DPS — 후순위

공격속도 단계, 실제 연계 시간, 콤보 획득·소비·유지시간, 사용 비중, 이동·캔슬·재사용시간을 확보한 경우에만 검토한다. 고정 콤보 상태의 환산공 상승률을 실제 지속 DPS 상승률로 확정하지 않는다.

## 5. 실측 계획과 판정 방법

| 검증 묶음 | 통제·변경 조건 | 판정 대상 |
| --- | --- | --- |
| 스탯공 | 순수 스탯·레벨 고정, 장비/버프를 한 번에 하나만 변경 | 최종 STR/DEX·총공격력·최대 스탯공의 정수 일치 |
| 공% 적용 | 비슷한 조건에서 장비 공%, 콤보 효과, 마스터리 공격력을 분리 | 장비/패시브/버프 중 공%가 곱해지는 출처 |
| 콤보 경계 | 우선 C=0/9/10/19/20/99/100/101, 추가 소비 문턱은 자료 확인 후 설정 | 단계 경계·상한·소비 전후 효과와 상태 초기화 |
| 크리 중첩 | 같은 콤보에서 외부 크리 버프 없음/쓸샾/샤프아이즈, 타격별 일반·크리 분리 | 확률·증가분·가산/승산·중첩 관계 |
| 분산 | 동일 종 몬스터 1/2/6마리부터 비교, 레벨은 확보 가능한 복수 구간·홀수 레벨 포함 | 대상 수·레벨 의존과 버림, 지원 최대 대상 수 |
| 특수 조건 | 보스/일반, 템페스트 빙결 전후, 속성 중립/약점/반감 | 예외식과 일반식의 분기 |
| 후보 교체 | 같은 스킬·콤보·버프·대상에서 서로 다른 장비 세트 최소 3개를 목표로 비교 | 최대 스탯공·환산공·상승률 검산, 특정 사진 맞춤 방지 |

수치 3세트와 경계 표본은 조사 제안이며 통계적 정확도 보장을 뜻하지 않는다. 모든 조합을 무작정 곱하지 않고 먼저 단일 변수 시험을 한 뒤 상호작용이 의심되는 조합을 추가한다.

- 확보할 자료: 현재 패치 시점·레벨·순수 STR/DEX·장비 옵션·관련 스킬 레벨·활성 버프·공격 전후 콤보가 보이는 기록, 스탯창, 대상 정보, 일반/크리 구별이 가능한 타격 기록. 게임 조작과 측정은 플레이어가 직접 수행하고 제공된 자료를 분석한다.
- 스탯창은 반올림·버림 규칙을 적용한 정수의 정확한 일치를 요구한다. 차이가 나면 오차를 허용하기 전에 누락된 출처와 순서를 추적한다.
- 실제 타격은 조건별 예비 표본을 모아 변동폭을 확인한 뒤 표본 수를 정한다. 평균·분산·크리 비율과 신뢰구간으로 가설을 비교하며 관측 최댓값을 이론상 최댓값으로 간주하지 않는다. 구분 불가능한 가설은 미확정으로 남긴다.
- 자료는 `공식 명시 / 실측 일치 / 공식과 실측 충돌 / 가설 / 미확인`으로 구분하고 각 판정에 근거를 연결한다.
- 개인 스크린샷·영상·OCR 원문은 Git 제외 `output/`에만 보관하고, 공유 문서에는 개인정보를 제외한 조건·요약·근거 경로만 기록한다.

## 6. 현재 앱과 연결할 조사 결과

2026-09-29 코드 확인 기준:

- `features/calculator/domain/job-rules.ts`: 지원 무기는 석궁·총·아대, 무기 계수 타입은 3.6, 기본 크리 값은 직업 상수다. 아란의 폴암·조건별 효과를 표현할 추가 모델이 필요한지 검토한다.
- `features/calculator/domain/formulas.ts`와 `calculate.ts`: 크리 기대 보정은 단일 스킬 배율과 기본/외부 버프 값을 사용한다. 콤보·연계 타격 조건을 기존 공통식과 어디서 분리할지 조사 결과로 결정한다.
- `features/calculator/domain/types.ts`, `storage.ts`: 직업 목록과 저장 검증에 아란이 없다. 후속 구현에는 기본값·저장 호환·세팅 전환 검증이 필요하다.
- 장비 인식·착용 조건·후보 비교·옵션 효율·시뮬레이터도 영향 범위에 포함한다. 폴암 분류, STR/DEX 매핑, 요구 조건, 발사체 공격력의 직업별 적용 여부와 기존 값 보존을 확인한다.
- 아란 장비 사진도 D-148의 오류 보정 개입 0회 기준으로 검증할 항목에 포함한다. 계산 연구만으로 무수정 인식 목표를 달성했다고 표현하지 않는다.

## 7. 조사 완료와 구현 착수의 구분

우선 산출물은 스킬표, 공식 변경 이력, 계산식 명세, 검산 사례, 미확정 목록, 최소 구현 범위다. P0 규칙은 각각 근거·단위·조건·현재 적용 시점을 갖추고, 확정할 수 없는 수치는 공란/미확정으로 남긴다.

최소 구현 후보는 아란 장비 등록·저장, 검증된 조건에서의 최대 스탯공, 동일 전투 조건의 후보 비교다. 환산공은 크리·대표 스킬 모델이 검증된 범위에서만 제공하고, 스킬 피해·연계 DPS는 별도 검증 완료에 따라 추가한다. 이것은 제안이며 구현 승인 또는 공개 범위 확정이 아니다.

이번 작업은 조사계획 수립과 문서 기록에 한정한다. D-027의 기존 계산 유지, D-135~136의 캡틴 베타, D-146의 명시적 요청에 따른 Production 배포, D-148의 인식 품질 목표를 변경하지 않는다.
