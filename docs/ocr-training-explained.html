01 · 전체 흐름에서 이번 학습의 위치

‘찾기’와 ‘읽기’는 다른 일입니다

스크린샷을 넣으면 곧바로 숫자가 나오는 것처럼 보여도, 안에서는 여러 단계를 거칩니다. 이번에는 그중 잘라 놓은 숫자 이미지를 읽는 모델을 학습했습니다.

숫자 읽기 — 잘라 놓은 이미지가 어떤 문자열인지 예측

기존 한국어 Paddle 인식 모델을 미세조정했습니다. 숫자 모양을 보고 문자열을 내는 부분의 가중치를 바꿨으며, 숫자만 허용하는 사전이나 강제 문자 치환은 사용하지 않았습니다.

위 단계를 누르면 각 역할을 볼 수 있습니다.

먼저 확인한 질문

영역이 온전하면 더 잘 읽을까?

원본에서 숫자 전체가 들어 있는 영역을 검수해 자르고, 기존 모델과 학습 모델에 같은 이미지를 넣었습니다.

그다음 확인한 질문

전체 사진에서도 효과가 이어질까?

좌표를 알려주지 않고 설명창과 숫자 영역을 자동으로 찾게 했습니다. 앞 단계에서 못 찾은 값도 실패로 셌습니다.

이번 대상은 요구 레벨과 STR·DEX·INT·LUK의 정수 값입니다. 장비 분류·옵션명·%·저장까지 모두 해결한 모델을 만든 것은 아닙니다.

02 · ‘모델을 학습한다’는 뜻

정답과 비교하며 내부 숫자를 조금씩 조정했습니다

출발점은 공식 한국어 PP-OCRv5 mobile 인식 모델입니다. 처음부터 글자를 가르치는 대신, 이미 배운 모델을 게임 숫자에 적응시키는 미세조정을 했습니다.

위 숫자와 예측은 원리 설명용 예시입니다. 특정 사진의 실제 학습 로그를 재현한 그림은 아닙니다.

모델이 틀렸을 때 결과 문자열을 억지로 고쳐 저장한 것이 아닙니다. 학습할 때만 정답으로 오차를 계산하고, 실제 판독에는 이미지와 모델만 전달했습니다. 정답표는 판독이 끝난 뒤 별도 채점기가 사용했습니다.

실제로 사용한 학습 설정
  • GPU: 로컬 RTX 3070 Ti 8GB, WSL의 전용 Python/Paddle 환경.
  • 학습 batch 16, 학습률 0.00003. 앱의 문자 인식 batch 6과는 다른 값입니다.
  • 원색 숫자 영역을 nearest 방식으로 3배 확대하고, 모델 입력 높이 48에 맞춰 크기·색상·정규화를 처리했습니다.
  • 기존 한국어 사전과 일반 CTC 디코딩을 유지했습니다. 숫자만 허용하는 출력 제한이나 O→0 같은 치환을 학습 효과로 섞지 않았습니다.
  • 기존 구조의 CTC + NRTR 손실을 사용했습니다. 정확도 평가는 오차값이 아니라 모델이 실제 출력한 문자열로 했습니다.
한 번 학습하고 끝내지 않은 이유

학습 자료를 잘 맞히는 것만으로는 부족하기 때문입니다. 같은 사진을 외우거나, 잘 읽던 숫자를 망가뜨릴 수도 있습니다. 매개변수 저장/복원, 다른 자료의 정확도, 기존 정상 사례의 회귀, 브라우저 변환까지 따로 확인했습니다.

모델과 Adam 최적화 상태는 읽기 직후 정확히 복원됐지만, 이어서 GPU 계산을 한 뒤에는 아주 작은 수치 차이가 남았습니다. 이를 완벽한 비트 단위 재현이라고 기록하지 않았습니다.

03 · 데이터가 섞이면 점수를 믿기 어렵습니다

공부할 자료와 마지막 시험지를 분리했습니다

학습

정답을 보며 푸는 연습문제

이미지와 정답을 사용해 가중치를 바꿉니다.

검증

학습 중 보는 모의고사

직접 학습하지 않고 언제 멈출지·어느 모델을 고를지 판단합니다.

최종시험

모델을 고른 뒤 여는 시험지

모델과 전처리를 고정한 뒤 평가합니다. 점수를 보고 유리한 후보로 바꾸지 않습니다.

이번에 사용한 자료 — ‘사진 수’와 ‘숫자 영역 수’는 다릅니다
자료숫자 영역출처와 용도
기존 캡틴 학습38 → 95개같은 19장에서 LEV·STR 38개를 먼저 사용하고, DEX·INT·LUK 57개를 추가했습니다.
기존 아란 검증38개19장의 기존 자료입니다. 개발 중 모델 선택용이며 새 독립 최종시험이 아닙니다.
기존 진단·반례10개보너스 값 2개와 기존 별도 사진 4장의 요구치 8개입니다. 이미 알려진 실패를 추적했습니다.
새 캐릭터·장비 시험70개사용자가 제공한 새 사진 14장 × 요구치 5개입니다. 학습·증강에 넣지 않았습니다.

143개는 확장한 학습 95 + 기존 검증 38 + 진단 10입니다. 새 시험 70개와 다른 집합이며, 새 사진 143장이 아닙니다.

같은 장비를 연속 촬영하거나 같은 사진을 확대·압축한 것은 독립 사례로 세지 않았습니다. 새 14장도 촬영 세션은 1개이며, 같은 벨트로 보이는 2장을 묶어 장비 그룹을 보수적으로 13개로 기록했습니다.

정답과 자료가 바뀌지 않았는지는 어떻게 확인했나?

파일과 잘린 이미지에 hash(내용을 확인하는 지문)를 붙였습니다. 정답·좌표·출처·분할·모델 지문을 기록한 목록을 고정한 뒤 실행했습니다. 숫자가 잘리지 않았는지 같은 에이전트가 원본과 두 번 대조했으며, 독립된 두 사람이 검수했다고 표현하지 않았습니다.

새 사진은 정답 작성 전 모델을 고정하고, 추론 전 정답과 영역을 봉인했습니다. 출력 결과를 본 뒤 정답·좌표를 고치거나 실패 사례를 분모에서 빼지 않았습니다.

04 · 성공한 시도와 실패한 시도

학습을 더 했다고 항상 좋아지지는 않았습니다

1

학습 전에 같은 모델인지부터 확인

앱에 있는 모델(A1)과 공식 학습 가중치를 학습 없이 변환한 모델(B0)을 같은 브라우저 입력으로 비교했습니다. 변환 차이를 학습 효과로 오해하지 않기 위한 기준선입니다.

같은 입력의 A1/B0 브라우저 출력 일치 확인
2

첫 일반 미세조정은 성능이 떨어짐

38개로 학습했지만 기존 검증 38개의 정답 수가 26개에서 14개로 줄었습니다. 학습이 정상 실행된 것과 좋은 모델이 나온 것은 별개였습니다.

검증 26/38 → 14/38 · 이 후보는 제외
3

BatchNorm의 기준 통계를 고정한 실험

작은 표본으로 평균·분산 기준까지 바뀌는 영향을 줄이기 위해, 사전학습된 BatchNorm의 누적 통계를 유지했습니다. 나머지 가중치와 학습 가능한 계수는 계속 갱신했습니다.

BN1: 학습 38/38 · 기존 검증 38/38 · 진단 10/10

다른 seed 2회도 같은 점수였습니다. 이 결과만으로 첫 실패의 원인이 하나였다고 확정하지는 않았습니다.

4

실사만 학습 vs 외형을 변형한 이미지도 학습

학습 숫자를 확대·축소하고 명도·약한 흐림·여백을 바꿔 3,040개 파생 이미지를 만들었습니다. 원본/정답을 보여주는 순서를 맞춰 비교했습니다.

첫 증강군: 검증 이득 없음 · 학습 37/38 · 진단 9/10 → 채택하지 않음
5

학습 영역을 95개로 넓혀 다시 비교

기존 학습 사진에서 쓰지 않던 요구치 57개를 더해 숫자 9를 확보했습니다. 두 방식 모두 기존 143개를 맞혔지만, 기존 BN1도 같은 결과라 추가 이득은 확인하지 못했습니다.

새 체크포인트 보존 · 기존 BN1 유지

파생 이미지 3,040개 ≠ 새로운 실제 사진 3,040장. 같은 숫자의 외형을 바꾼 자료입니다. 새로운 글꼴이나 없는 숫자를 완성한 합성 학습은 아닙니다. 현재 확장 학습에는 숫자 3·6이 없습니다.

모델을 고르고 멈춘 기준을 자세히 보기

초기 파일럿은 20 epoch의 마지막 모델을 확인했습니다. 뒤의 비교 학습에서는 매 epoch마다 검증하고, 기준보다 정확도가 좋아지면서 틀린 숫자 증가·기존 정상 회귀가 없는 후보를 골랐습니다. 같은 최상 점수라면 가장 이른 epoch를 택하고, 5회 연속 개선이 없으면 멈췄습니다.

같은 비교 안에서는 원본·정답 노출을 맞췄습니다. 다만 38개와 95개 실험은 epoch당 갱신 횟수도 달라, 두 실험의 차이를 순수한 자료 수 증가 효과로 단정하지 않았습니다.

05 · 가장 중요한 결과 해석

69/70과 63/70은 무엇이 다른가요?

둘 다 새 사진 14장의 요구치 70개를 대상으로 합니다. 숫자 영역을 미리 검수해 주었는지, 시스템이 직접 찾아야 했는지가 다릅니다.

숫자가 온전히 들어 있는 영역을 같은 조건으로 잘라 두 모델에 입력했습니다.

수동 영역과 자동 영역은 폭·높이·배경이 다릅니다. 기존 모델도 수동에서는16/70, 자동에서는60/70을 냈습니다. 두 조건의 잘 나온 값만 골라 합치지 않고, 같은 입력 안에서 모델을 비교했습니다.

숫자 몇 개가 맞는 것과 장비 한 개가 완성되는 것은 다릅니다

요구치 5개가 모두 맞아도 공격력·잠재 옵션·%·분류·미해결 검토까지 남아 있을 수 있습니다. 자동 시험에서 학습 모델이 요구치 5개를 모두 맞힌 사진은 11/14장이었지만, 이것을 장비 전체 성공률로 세지 않았습니다.

해석의 범위

실제 저장 성공을 측정한 수치가 아닙니다

차단 없는 3장은 후행 대조에서 분류·매핑 필드가 맞았지만, 실제 적용·저장·독립 사용자 POC까지 검증한 것은 아닙니다.

연구용 숫자 후보의 출력을 실제 제품 검토값에 주입하지 않았습니다. 후보의 숫자 오류를 실제 오저장 건수로 계산하지 않았습니다.

06 · 학습한 모델을 실제 실행 환경으로 옮기기

GPU에서 배운 모델을 브라우저에서도 확인했습니다

1. 로컬 GPU 학습가중치와 학습 상태를 체크포인트로 저장
2. ONNX 변환브라우저가 실행할 수 있는 모델 형식으로 내보내기
3. 브라우저 실행실제 SDK + WASM, 같은 이미지와 사전 사용
4. 출력 대조원문 문자열·모델·입력 지문을 비교

이번 브라우저 시험은 WASM으로 실행했습니다. 학습할 때 GPU를 썼다는 말이 사용자 브라우저에서도 GPU 학습을 한다는 뜻은 아닙니다. 사진과 정답을 외부 OCR 서버로 보내지도 않았습니다.

같은 모델인데 GPU와 브라우저가 다른 글자를 낸 이유

학습 전 모델에서 2개 문자열이 달랐습니다. 실제 입력 텐서를 저장해 비교하니 픽셀·패딩은 같았습니다. CPU에서는 같은 문자를 냈고, GPU의 TF32 관련 정밀도 설정을 바꾸자 차이가 없어졌습니다.

NVIDIA_TF32_OVERRIDE=0으로 고정한 대조에서 4개 모델 × 143개 입력의 GPU·브라우저 문자열이 각각 일치했습니다. 정답률은 바뀌지 않았고, 틀린 답은 같은 틀린 답으로 남을 수 있습니다.

이는 실행 환경의 수치 계산 차이를 좁힌 결과입니다. 모든 확률값이 비트까지 같아진 것은 아니며, 모든 사진·기기에서 항상 같은 결과를 보장하는 것도 아닙니다. 이후에는 정밀도 설정도 기록하고 다른 설정으로 이어 학습하지 못하게 검사합니다.

속도·메모리·취소는 어디까지 확인했나?

숫자 영역을 처리하는 실제 별도 Worker에서 배치1/6, 재사용, 초기화/판독 중 취소, 재시작을 확인했습니다. 취소 후 결과 채택은0개였고 재시작 결과는 같았습니다. 제품 전체의 적용·저장 흐름 검증과는 구분합니다.

86개 숫자 영역, 같은 PC기존 A1학습 BN1
반복 판독 시간 중앙값4.22초4.34초
최대 Private Bytes의 trial 중앙값1,096MiB1,048MiB

두 모델을 함께 상주시킨 별도 시험은 약1,474MiB였습니다. 작은 단일 기기 표본이며 속도·메모리 개선이나 모든 기기의 보장으로 표현하지 않았습니다. 4.34초를 전체 장비 사진 한 장의 처리 시간으로 읽으면 안 됩니다.

07 · 지금 어디까지 왔고, 무엇이 남았나

모델 개선은 확인했지만 적용 기준은 아직 못 넘었습니다

  • 확인로컬 학습·저장/복원·변환·브라우저 실행, 기존/학습 모델의 통제 비교.
  • 확인새 사진의 온전한 숫자 영역에서 인식 개선: 16/70 → 69/70.
  • 미통과새 숫자 시험 99% 목표. 자동 처리에는 추출 실패6개·숫자 오류1개가 남음.
  • 남은 일다양한 촬영·숫자3/6·검증된 글꼴 조합, 새 후보의 미사용 최종시험, 장비 전체·적용/저장 검증.
  • 보류실제 제품 모델 교체와 운영 배포. 이번 연구 결과만으로 공개 모델을 바꾸지 않음.

추가 사진은 왜 필요한가요?

기존 검증 자료를 모두 맞히는 모델끼리는 그 점수로 우열을 가리기 어렵습니다. 새 사진을 본 뒤 모델을 다시 조정했다면, 이전 시험은 더 이상 새 후보의 ‘처음 보는 시험지’가 될 수 없습니다. 다른 장비·촬영 조건의 실제 사진이 필요합니다.

다음 소규모 실험을 위한 제안

추가 30장 정도부터

학습15 · 검증5 · 최종시험10장의 예시입니다. 같은 장비·연속 촬영은 한 묶음으로 두므로, 실제 분할은 출처를 확인한 뒤 조정합니다. 30장을 모으면 자동으로 합격한다는 뜻은 아닙니다.

  • 서로 다른 장비와 배경, 배율·밝기 조건을 섞기.
  • 가능하면 요구치에 3·6이 들어간 사진 포함하기. 9는 기존 자료에서 추가 확보했습니다.
  • 설명창 전체와 마지막 옵션이 보이도록 촬영하기.
  • 같은 장비를 다시 찍은 경우 그 사실을 함께 알려주기.

계획서의 정식 최종시험 수집 제안은 숫자300개·원본 그룹50개 이상입니다. 사진당 유효 요구치5개라면 시험용만 약60장에 해당하며, 촬영 그룹의 다양성도 별도로 필요합니다.

현재 상태: 추가 자료 대기. GPU 학습·평가와 실험용 서버/브라우저는 종료한 상태입니다. 이 문서를 여는 동작은 학습을 시작하지 않습니다.

08 · 필요할 때 다시 보는 설명

용어와 확인 근거

헷갈리기 쉬운 용어
OCR
이미지 속 글자를 문자열로 읽는 기술입니다. 여기서는 위치 찾기와 글자 읽기를 나누어 봤습니다.
가중치
입력을 어떤 특징과 문자로 해석할지 결정하는 모델 내부의 수많은 계수입니다.
미세조정
이미 학습된 모델을 내 데이터로 추가 학습하는 것입니다.
batch
한 번에 묶어서 처리하는 입력 수입니다. 학습16과 앱 인식6은 서로 다른 설정입니다.
epoch
정해 둔 학습 자료를 한 차례 순회하는 단위입니다. 순회할 때마다 가중치를 여러 번 갱신합니다.
BatchNorm
신경망 중간값을 정규화하는 구성요소입니다. 이번 후보는 누적 평균·분산 통계를 고정하고 학습했습니다.
CTC
이미지의 여러 위치에서 나온 문자 후보를 중복·공백 규칙에 따라 문자열로 읽는 방식입니다. 이번에는 숫자만 허용하는 제약을 추가하지 않았습니다.
회귀
이전에는 맞히던 입력을 새 모델이 틀리는 현상입니다. 재학습 뒤 따로 확인했습니다.
체크포인트
모델 가중치와 학습 상태를 저장한 시점입니다. 나중에 평가하거나 학습을 이어 갈 때 사용합니다.
ONNX
학습한 모델을 다른 실행 환경으로 옮기는 데 사용한 형식입니다.
Worker
브라우저 안에서 작업을 따로 수행하는 실행 공간입니다. 사용자의 서버에 사진을 보내는 것과 다릅니다.
출력 일치
두 환경이 같은 문자열을 냈다는 뜻입니다. 두 환경 모두 같은 오답을 낼 수 있으므로 정확도와 별개입니다.
실험 이름을 기술 문서와 연결하기
  • A1: 기존 앱 인식 모델에 숫자 영역을 입력한 기준.
  • B0: 공식 학습 가중치를 추가 학습 없이 변환한 기준.
  • B1: 첫 일반 BatchNorm 학습. 성능 퇴행으로 제외.
  • BN1: BatchNorm 누적 통계를 고정한 실사38개 학습 후보. 새 시험에 사용한 모델.
  • C0 / C1: 각 비교 실험 안의 실사 반복 / 실사+외형 증강 모델. 서로 다른 실험의 같은 ID는 같은 가중치를 뜻하지 않습니다.
