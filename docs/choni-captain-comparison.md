# 초니 계산기 건슬링거와 현재 캡틴 계산 비교

확인일: 2026-09-27 (KST). 비교 대상은 [초니 계산기 물리 탭](https://choni-calc.vercel.app/#phy)의 건슬링거이며, 실제 계산 문서는 [공개 /phy 페이지](https://choni-calc.vercel.app/phy)다. 사이트 화면의 버전 표시는 **v1.29 · 2026-09-24 기준**이다. 이는 사이트 버전 표시이며 동일 날짜의 게임 패치를 검증했다는 의미는 아니다.

공개 HTML/JavaScript와 실제 브라우저 결과를 확인했다. 일반 웹 조회 도구는 접근하지 못했지만 HTTP 요청과 Chromium 브라우저에서 정상 접근했다. 비교용 숫자는 임의로 만든 합성 입력이다. 사용자 사진·장비 세팅은 외부 사이트에 입력하지 않았다. 앱의 공식은 변경하지 않았다.

## 결론

**건슬링거와 캡틴이라는 이름 차이에도 기본 총 무기 계산 계수와 주요 보정 구조는 유사하다.** 결과가 달라지는 주요 원인은 스탯의 반올림/버림, 데미지 단계의 절사 위치, 합산 크리 확률 상한, 실제 입력되는 순수 스탯이다.

참고 사이트의 **보스 대상 크리 반영 기대 데미지**가 우리 앱의 보스 프리셋 **환산공격력**에 가장 가까운 비교 대상이다. 참고 사이트의 일반 최대값·최소값·DPS를 우리 환산공과 그대로 비교하면 지표가 달라진다. 현재 POC는 실제 DPS를 계산하는 것으로 확정되지 않았다.

## 계산 구조 비교

아래 `DEX`, `STR`은 장비·버프 처리 후 최종 스탯, `A`는 최종 공격력, `p`는 크리 확률(%), `c`는 추가 크리 데미지(%p), `s`는 스킬 배율(%)이다.

| 항목 | 초니 건슬링거 | 현재 우리 캡틴 |
| --- | --- | --- |
| 무기 계수 | DEX에 3.6 | DEX에 3.6 |
| 기본 최대 스탯 부분 | `(3.6 × DEX + STR) × A / 100` | 같은 구조 |
| 순수 스탯 | 사용자가 넣은 순수 주·부스탯을 기준으로 유지 | 앱 입력 경로는 레벨·장비 요구치로 자동 배분하는 코드가 남음 |
| 잠재 반영 스탯 | `(순수 + 장비) × (1 + 스탯%/100)`을 반올림 | 같은 항을 버림 |
| 메이플 용사 | 순수 스탯에만 적용한 값을 버림 후 별도 가산 | 같은 구조 |
| 공격력% | 아이템 공격력에 적용해 버림, 탄약·축복·길드·버프 등을 평면 가산 | 같은 큰 구조. 일반 장비와 평면 가산 슬롯을 분리 |
| 총뎀·보공 | 보스는 합산, 일반은 총뎀만 | 보스는 합산, 사냥은 보공 제외 |
| 방어율 | 몬스터 방어율에서 방무를 차감 | 같은 방식. 우리 함수는 최종 배율 하한 0도 보장 |
| 크리 보정 | `1 + (p/100) × (c/s)` | 같은 식 |
| 합산 크리 확률 | 기본+무기 크확을 100%에서 제한 | 추가 크확·직업 기본·샤프아이즈를 더한 뒤 100% 제한 없음 |
| 크리 입력 | 기본 크확·무기별 크확·크뎀·스킬% 직접 입력 | 캐릭터 추가 크확·샤프아이즈와 스킬% 사용. 캡틴 기본 스킬%는 380 |
| 최소값 | 숙련도로 별도 계산 | 최소 스탯공/최소 데미지 계산 없음 |
| 공격 속도 | 공격 속도 등급으로 DPS 보조 수치 계산 | 공격 속도·DPS 계산 없음 |

올스탯 입력 방식도 맞춰야 한다. 참고 사이트는 주스탯 쪽 올스탯 효과를 장비 주%에 포함하고 별도 올스탯% 칸을 부스탯에 적용한다. 우리 OCR 매핑은 올스탯을 주·부스탯 양쪽으로 배분한다. 동일 이름의 입력 칸에 같은 숫자를 넣는 것만으로 동일 조건이 되지는 않는다.

우리 코드 근거: [무기 계수](../features/calculator/domain/job-rules.ts), [공식](../features/calculator/domain/formulas.ts), [캐릭터/버프 합성](../features/calculator/domain/calculate.ts), [공격력 출처 분리](../features/calculator/domain/equipment.ts), [올스탯 매핑](../features/calculator/ocr/mapRecognizedStats.ts).

## 절사 위치의 차이

공통의 절사 전 최대 스탯 값을 `R`, 데미지 배율을 `D`, 방어율 배율을 `F`, 크리 배율을 `C`라 하면 코드 구조는 다음과 같다.

- 우리 앱: 먼저 `floor(R)`로 최대 스탯공을 만들고 `floor(floor(R) × D × F × C)`를 반환한다.
- 참고 사이트: `floor(R × D × F)`를 먼저 구하고 크리 배율을 곱한 뒤 다시 버린다.

수학적으로 절사 위치가 다르므로 같은 최종 스탯이어도 정수 결과가 조금 달라질 수 있다. 참고 사이트와 숫자를 맞추기 위해 어느 한쪽으로 임의 변경하면 안 된다. 실제 게임에서 반올림 경계가 드러나는 조건과 공식 근거를 확인해야 한다.

## 실제 브라우저와 로컬 함수 대조

참고 사이트의 건슬링거 탭에서 합성 입력으로 계산했다. 우리 쪽은 실제 `calculateFromSnapshot` 함수를 호출하되 순수 스탯을 명시해, 이번 수치 비교에서 자동 배분 차이를 제거했다. 따라서 이 표는 **계산 함수 비교**이며 현재 UI의 능력창 자동 등록이나 순수 스탯 고정이 완성됐다는 뜻이 아니다.

| 조건 | 우리 환산공 | 참고 사이트 보스 기대값 | 확인한 차이 |
| --- | ---: | ---: | --- |
| 기본 합성 조건 | 7,839 | 7,838 | 데미지 절사 순서 차이 |
| 순수 DEX 1,008, DEX 9%, 공격력 100, 나머지 보정 없음 | 3,956 | 3,960 | 최종 DEX가 우리 1,098 / 사이트 1,099 |
| 다른 절사 대조 조건 | 2,496 | 2,496 | 절사 순서가 달라도 이 조건에서는 결과 일치 |
| 크확 합계 115%가 되는 조건 | 10,576 | 10,164 | 우리 115% 사용 / 사이트 100% 제한, 절사 차이도 포함 |

기본 합성 조건: 순수 DEX 1,000·STR 4, 장비 DEX 200·STR 100, DEX% 20·STR% 10, 메용 10%, 아이템 공격력 120·공격력% 10·평면 공격력 70, 총뎀 10·보공 20, 방어율 80·방무 30, 크확 15·크뎀 140·스킬% 380이다. 크확 상한 사례는 같은 조건에서 샤프아이즈 외 추가 크확을 100으로 올렸다.

### 우리 코드에서 보완이 필요한 점

현재 추가 크확 입력 자체는 0~100으로 검증하지만, `calculate.ts`가 샤프아이즈 등의 확률을 더한 뒤 `calculateCriticalMultiplier`에 넘길 때 상한을 적용하지 않는다. 예를 들어 추가 크확 100 + 샤프아이즈 15는 115가 된다. 확률 경계가 빠진 것으로 보이며, 최종 합계에 100% 상한을 적용하는 정책과 회귀 테스트를 보완해야 한다.

스탯 반올림 차이는 별도 판단 대상이다. 참고 사이트가 반올림한다는 사실만으로 우리 버림 처리가 틀렸다고 확정할 수 없다. 공개 소스에 실측 관련 주석이 있지만 그것이 우리 프로젝트의 독립 실측 검증을 대신하지는 않는다.

## 비교 UI에서 그대로 따르지 말아야 할 부분

참고 사이트의 무기 A/B 승자 문구는 양쪽 우열 모두 **B값을 분모**로 사용한다. 브라우저에서 A 3,600 / B 3,960을 만들자 `9.1% 우세`가 표시됐다. A를 현재 장비, B를 구매 후보로 해석한다면 실제 현재 대비 증가율은 `(3,960 / 3,600 - 1) × 100 = 10%`다.

따라서 우리 POC는 확정한 대로 **항상 현재 장비 값을 분모로 사용**해야 한다. 사이트의 다른 DPS 비교 문구는 이 예시에서 10.0%를 표시하므로, 이 지적은 특정 A/B 승자 문구의 계산에 해당한다. 참고 사이트 전체가 같은 분모를 사용한다고 일반화하지 않는다.

## 최소값·DPS를 해석할 때의 주의점

참고 사이트의 최소값은 DEX 항에 `0.9 × 숙련도`를 적용한 별도 계산이다. 크리 반영 기대값은 최대값에 크리 확률 보정을 적용하며 최소~최대 구간 전체의 평균을 구하는 코드가 아니다.

또한 공개 `/phy` 코드에서는 스킬%를 크리 보정의 분모로 사용하지만 최종 결과에 스킬 배율과 타수를 별도로 곱하지 않는다. DPS 보조값은 이 기대값에 공격 속도 등급의 초당 횟수를 곱한다. 코드 해석상 이를 캡틴의 특정 스킬 실전 DPS와 동일하다고 보장할 수 없다. 우리 환산공도 같은 이유로 실제 스킬 피해량과 구분해야 한다.

## 권고

후속 개인 세팅 대조에서는 사용자 원본을 검토해 합산했을 때 **현재 앱의 스탯 버림 방식이 능력창의 최종 스탯과 최대 스탯공을 재현했다.** 참고 사이트의 반올림 방식은 소폭 높은 값을 냈다. 이 한 세팅은 버림을 유지할 근거를 보강하지만 크리·방어율·실전 DPS 전체를 입증하지는 않는다. 개인 이미지·세부 옵션·계산표는 공개 문서에 복제하지 않고 Git 제외 경로 `output/choni-comparison/real-gear/results.md`에 보존한다.

1. 기존 3.6 계수·공격력 출처 구분·방어율·크리 보정의 큰 틀은 유지하면서 근거를 검증한다.
2. 능력창에서 확인한 실제 순수 스탯을 고정하는 POC 작업을 우선 진행한다.
3. 합산 크리 확률 상한을 보완할 대상으로 기록한다.
4. 스탯 버림은 확인한 실제 세팅의 일치를 근거로 유지할 수 있다. 추가 세팅의 경계 사례와 중간 데미지 절사 위치는 별도로 확인한다.
5. 후보 상승률은 항상 현재 장비 기준으로 계산한다. 참고 사이트의 승자 배지·가성비·DPS 기능을 이번 POC 범위에 자동 추가하지 않는다.
